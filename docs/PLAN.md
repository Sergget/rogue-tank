## 2. 近远期执行路线（2026-10-26 重排）

> **目标**：保留现有二维战术判定与 Roguelike 系统，把单机体验推进到「精细真 3D 战场 + 有重量感的载具 + 少量可指挥友军」。参考《变节行动》的驾驶、破坏、演出与场景品质，**不复制其多人模式，不以美术参考名作为功能承诺**。
>
> **本节是排期与验收门，不是完成记录**。机制细则归 `docs/specs/combat/ally-command.md`、`docs/specs/map/rendering-roadmap.md`；实现并验证后逐条删除、归档，历史路线仍可在 specs 的沿革注记追溯。

### 2.1 已裁定边界

| 维度 | 裁定 |
|---|---|
| 游戏形态 | 单机玩家战车 + **少量 AI 友军** + 实时战术命令；首个可玩切片以 **2～4 辆友军**为设计容量，数值须实测标定 |
| 多人 | **不做本地或在线多人合作**；近期/远期均不以网络同步、房间、联机存档或多人反作弊为前置 |
| 渲染方向 | **不再把 Canvas 路线 A 当最终品质路线**；首选 Three.js/WebGL 真 3D 垂直切片，通过后再渐进替换战斗绘制 |
| 模拟边界 | 甲弹对抗、卡牌、AI、移动与节点流程继续以二维世界为权威；视觉悬挂、碎片和刚体不得反向制造不确定的命中结果 |
| 引擎 | **现在不全量换 Unity/Godot、不重写游戏**；切片失败时才做 Godot 等备选评审，须以实测证据而非引擎名气决定 |
| 美术 | 参数化挤出只用于灰盒与原型；精细模型、PBR 材质、地表、损坏状态和特效另设资产生产管线，不以「无需建模」推导「无需美术」 |
| 相机 | 先验证固定俯视/轻倾斜与鼠标地面拾取；**可旋转相机、高度地形与 3D 弹道均不默认纳入** |

### 2.2 近期顺序：先清账，再做两条可独立验收的切片

| 顺序 | 批次 | 内容 | 完成门 / 退出条件 |
|---|---|---|---|
| 0 | **存量 AA-a → AA-b → AA-c** | 公路 HUD、bench 曲射与运行时对齐、电磁炮充能/放电音效 | 依 §6 验收；不因远期重构把已确认缺陷留到新版再修 |
| 1 | **R0 渲染地基** | I3 浏览器截图基线、I4 拾取统一入口、固定 seed/相机/分辨率场景、性能计数与当前 Canvas 对照图 | 同输入可复现截图与鼠标世界坐标；记录基线帧率/内存/绘制成本；不先改正式战斗画面 |
| 2 | **A0 友军指挥逻辑原型** | 2～4 辆友军、六命令、单车/全体控制、统一目标选择、命令状态反馈；先在现有 2D 战斗验证 | 完整通过「跟随推进 → 集火指定重甲 → 驻守 → 残血撤退」；友军不再由 `nearestEnemyTo` 绕过集火目标；不可达/无射界可解释 |
| 3 | **R1 真 3D 可玩切片** | 同一张小战场接入现有模拟：1 辆玩家车 + 少量友军、道路/建筑/树石、轻倾斜相机、主炮命中、烟尘与基础破坏 | Go/No-Go 见 §2.3；与 A0 共用场景与命令脚本，避免只交付不可玩的渲染演示 |
| 4 | **G1 品质垂直切片** | 载具重量感、分级破坏、统一炮火/音效/震屏、精修单车与单主题场景、完整 3～5 分钟战斗 | 内部对照目标截图/录屏评审；驾驶、命中、命令、敌我识别均达标后才准批量生产资产 |
| 5 | **技术定型** | 根据 R1/G1 实测选择「保留 JS + Three.js 渐进替换」或重评其他引擎 | 输出迁移清单、性能预算、资产规格与存档/回归兼容方案；未过门不承诺最终引擎 |

A0 与 R1 可并行，但必须遵守单写者规则：AI/命令逻辑与 Three.js 场景/渲染解耦，正式 `tank_battle.html` 同批只能有一个接线写者。**R0 不是另造一套游戏，A0 也不等待真 3D 完成。**

### 2.3 R1 / G1 的 Go / No-Go 验收

| 维度 | 必须证明 | 不通过时的动作 |
|---|---|---|
| 操控与判定 | 地面拾取与现行 2D 坐标一致；同一输入回放的命中/伤害/AI 结果不变；轻倾斜下能读清射界与距离 | 修投影与输入，不改判定来迁就画面 |
| 画面与识别 | 1080p 实机尺度下玩家/友军/敌军、炮塔方向、掩体高度与危险区清晰；阴影/烟尘不得盖住致命信息 | 降效果、改镜头/材质，不进入量产 |
| 驾驶与战斗 | 加速/制动/侧倾/落地/碰撞有重量但不拖慢指令；口径差异在声画上可辨 | 先调车感与演出，不继续堆地图内容 |
| 友军指挥 | 六命令可发现、可撤销、可读状态；AI 不因自保健全抗命，也不挤车/堵路/擅自换集火目标 | 修命令状态机与协调层，不用增加友军数量掩盖 |
| 性能 | 记录 1080p 目标机与 Deck 档预算；正常战斗满足稳定帧时间，峰值爆炸/破坏有降级策略 | 实例化、LOD、碎片/阴影降档；不得以降模拟频率换帧率 |
| 工程 | 截图回归、确定性回放、存档迁移与现有测试可继续运行；Canvas 对照路径在迁移期可用 | 暂停扩面，先补工具链与回归 |

**禁止的假象**：一段相机运镜、一个高模、粒子数量很多、静态截图变漂亮，都不等于通过切片。验收必须包含可驾驶、可命中、可指挥和可重复测试。

### 2.4 远期量产顺序（G1 通过后才启动）

| 阶段 | 工作包 | 与既有规划的关系 |
|---|---|---|
| **M1 核心战斗量产** | 载具动力学与车型差异、分阶段环境破坏、战斗演出、镜头可读性、地表互动、友军职能/导航/命令构筑 | 扩展 §4 载具/撞击/烟幕/武器与 §5 音画，不重复造系统 |
| **M2 内容与重玩性** | 主题地图、巡逻/伏击/护送/增援遭遇、任务变体、Boss 演出、run 节奏与难度导演、车库/进阶/图鉴 | 接入 §4.1/4.4/4.6 与 §5.1.6；先证明内容组合，再扩数量 |
| **M3 商业发行** | 手柄与命令环、本地化、音频/设置/可访问性、性能档位、成就/云存档/崩溃日志、存档版本迁移与回放 | 细化 §5；多人反作弊、房间和联机同步不在范围 |
| **M4 可选扩展** | 创意工坊、排行榜、更多主题/载具；每日挑战须有回放与版本规则 | 仍按单机异步排行榜评估，不引申为实时多人 |

### 2.5 必须单独立项的远期工作包

1. **真 3D 渲染与资产管线**：glTF/纹理/材质、实例化、LOD、PBR/阴影、损坏状态和锚点验收；原型挤出与精修资产分级。
2. **载具动力学与重量感**：抓地、侧滑、坡面、悬挂视觉、俯仰/侧倾、腾空落地；二维权威模拟与视觉表现分离。
3. **环境破坏与连锁互动**：建筑/围墙/爆炸物状态、残骸与通路变化、油火/地表/烟幕联动；先定义玩法破坏和纯视觉破坏的边界。
4. **统一战斗演出**：口径分级、后坐、弹着材质、焦痕、持续火焰、震屏上限、声音与粒子共用强度语言。
5. **友军指挥完整链**：见 §3；职能编队、导航让行、状态 UI、语音、协同卡牌与针对性遭遇同属一个产品闭环。
6. **遭遇导演与地图任务**：主题区域、防线、伏击、精英组合、Boss 阶段与多目标，不靠纯血量/数量放大难度。
7. **Run 节奏与重玩性**：战斗/喘息/奖励节拍、压力预算、完整局时长、每日挑战、车库与进阶难度。
8. **商业品质基础设施**：性能预算、回放、版本化存档与迁移、崩溃诊断、I18n、手柄、Deck、可访问性和授权审查。

**路线优先级**：核心手感与可读性> 友军命令可靠性> 破坏与演出> 内容数量> 平台扩展。任何后级工作不得用内容数量掩盖前级未达标。

## 4. 既有远期模块与待补细目（Long-term Roadmap）

> **2026-10-26 重排**：以下既有模块全部纳入 §2.4 的 M1/M2，不再独立抢在 R0/A0/R1/G1 前开工；已完成机制只作能力基础，不在这里重复记完成状态。旧横向推进与 A/B/C 清账章节已经完结，原文归档至 `docs/archive/2026-10.md`。



### 4.1 载具主武器绑定与专属升级卡池（车库驱动化构筑）
- **核心逻辑变更**：
  1. **取消主武器更换/安装卡牌**：主武器改为与载具底盘深度绑定的固有硬装（Fixed Main Armament），彻底解决此前局内随机换装导致不同载具底盘特色被稀释的问题。
  2. **扩充可解锁车库阵容**：
     - 步兵战车（如 BMP 系列）：搭载 30mm 机关炮 + 100mm 低压线膛炮 / 反坦克导弹。
     - 坦克支援车（如 BMPT“终结者”）：搭载双联 30mm 自动炮 + 4 联装超音速重型反坦克导弹。
     - 现代主战坦克、突击炮与轮式底盘分化。
  3. **升级卡池动态自适应过滤（Adaptive Card Pool）**：
     - 根据当前出战载具绑定的主武器类型（机炮 / 滑膛炮 / 线膛炮 / 双联火炮 / 电磁轨道炮等），动态筛选升级卡池。
     - 机关炮专属升级：弹链扩容、高爆燃烧弹（HEI）、水冷枪管（散热速度加倍、热容上限提升）。
     - 滑膛/线膛炮专属升级：尾翼稳定脱壳穿甲弹（APFSDS）、破甲弹（HEAT-FS）、炮控计算机（三扩大幅压制）。
     - 电磁轨道炮专属升级：电容过载、贯穿电弧溅射等。
- **涉及系统**：`tank_model.js`、`tank_weapons.js`、`tank_cards.js`（`cardEligible` 判定）、`tank_flow.js`（选车加载）、`tanks/*.json`。

### 4.2 隐蔽机制与战场感知梯度（Stealth & Spotting System）
- **隐蔽系数矩阵（Camo Rating Calculation）**：
  - **吨位与车型基准**：轻型轮式> 履带步战车> 中型坦克> 重型主战坦克/自行火炮。
  - **运动状态修正**：静止（享受全额隐蔽加成） vs 移动（基础隐蔽削减 30%~50%）。
  - **开火惩罚（Muzzle Blast Penalty）**：开火瞬间由于火光、扬尘与巨大声响，隐蔽值暴跌 70%~90%，持续 3~5 秒后随烟尘散去平滑恢复。
  - **掩体与环境遮蔽**：
    - 处于树林、灌木丛（`foliage`）或战术烟幕中：获得极高隐蔽加成（隐蔽值 +50%~80%）。
    - 处于开阔平地、硬化公路：无环境隐蔽加成，全额暴露。
- **敌方 AI 感知梯度与反应分级（AI Awareness Gradient）**：
  - **未发现（Unaware / Idle）**：超出感知距离或隐蔽达标，AI 保持巡逻/站桩，不开火、不转向。
  - **警觉/搜索（Suspicious）**：察觉到附近炮火声、队友受击或视线边缘隐约目标，AI 炮塔转向疑点方向侦查，但射击精度受到极大散布惩罚。
  - **完全锁定（Spotted & Engaged）**：突破隐蔽临界点被点亮，AI 全力协同接战，并呼叫临近队友形成交叉火力。
- **涉及系统**：`tank_cover.js`、`tank_ai.js`、`tank_ai_squad.js`、`tank_rules.js`。

### 4.3 物理碰撞与撞击伤害（Ramming Physics & Damage Settlement）
- **结算公式与冲量模型**：
  - **受损核心因子**：双方重量（Mass）、相对碰撞速度（Relative Velocity 矢量投影差）、碰撞接触部位装甲厚度（Armor at Impact Point）。
  - **结算机制**：
    - 坚固厚装甲部位（如重坦首上）撞击敌方薄弱部位（如轻型车侧面/尾部）时，重坦几乎免疫撞击伤害，轻型车承受巨额毁灭性撞击伤害。
    - 双方速度对冲正面相撞时，按等效装甲差值及质量比分配伤害。
  - **物理反馈与附加效果**：
    - 剧烈撞击伴随屏幕震颤、金属刺耳擦挂音效与火花飞溅。
    - 概率造成履带断裂、车轮损毁、短时间转向失控（Stun/Immobilize）。
- **涉及系统**：`tank_physics.js`、`tank_entity.js`（`resolveTankCollisions`）、`tank_model.js`。

### 4.4 多元化特种载具与战术模式姿态
- **新增载具类型矩阵**：
  - **高机动轮式战车**（如 BTR、半人马座 Centauro、08 式轮突）：极高的公路巡航极速与机动灵活性，但泥泞/涉水减速惩罚更严苛，车体装甲偏薄，撞击抗性弱。
  - **无人炮塔 / 遥控武器站车辆**（如 食人鱼 Piranha、T-14 阿玛塔）：主炮塔内部无乘员舱，炮塔被击穿时大幅降低所受核心伤害（衰减 70%~80%），杜绝炮塔穿透殉爆。
  - **自行火炮**（如 PzH 2000）：具备超视距大口径曲射火炮，可跨越全高建筑与障碍进行范围高爆轰击，但近战自卫能力较弱，需依赖阵地与视野支撑。
  - **反坦克导弹发射车（ATGM Carrier）**：专职搭载重型反坦克导弹，高隐蔽、远射程、精准线导/发射后不管，近身遭遇战极度脆弱。
- **特种战术模式与技能机制**：
  - **氮气加速 / 发动机过载（Nitro / Engine Boost）**：短时间内（如 3~5 秒）大幅提升发动机马力与极速（+100%~150%），急加速伴随尾气气流粒子与发动机轰鸣，用于战术转场或强行脱离危险区。
  - **攻城模式（Siege Mode）**：驻车展开液压支架，限制车体移动速度与炮塔旋转角度，换取极致射击精度（散布收敛速度提升、移动与转动三扩极大降低）、大幅缩短装填时间与提升射程。
  - **防御/阵地模式（Defense / Fortify Mode）**：原地驻车并变形放下推土铲/展开重型附加侧裙板，无法移动，换取车体正面与侧面等效装甲大幅提升（如 +50%~100%），受爆炸与溅射伤害显著降低。
- **涉及系统**：`tank_move.js`、`tank_abilities.js`、`tank_weapons.js`、`tank_model.js`。

### 4.5 战术烟幕系统（Smoke Grenade & Engine ESS）
- **烟幕生成形态**：
  1. **抛射烟雾弹（Smoke Grenade Launcher）**：向前或周围 120° 扇区瞬时抛射多枚烟雾弹，形成大范围浓密烟墙。
  2. **发动机排气拉烟（Engine Smoke System, ESS）**：坦克移动过程中沿车体排气尾迹持续生成一条长条形烟雾带。
- **战术反制与战场机制**：
  - **视线绝对遮断（Line-of-Sight Break）**：处于烟幕内或视线被烟幕阻隔的单位瞬间脱离敌方视野，进入隐蔽态。
  - **红外/激光导弹软杀伤（Missile Soft-Kill）**：烟雾内悬浮颗粒阻断激光测距与红外制导，使来袭的制导导弹瞬间失锁并偏航脱靶。
  - **AI 动态响应**：敌方 AI 失去目标后不再进行精确锁敌，转为对烟雾区域进行盲射压制或向烟雾两侧包抄。
- **涉及系统**：`tank_cover.js`、`tank_weapons.js`（导弹寻的逻辑）、`tank_fire.js`、`tank_fx.js`。

### 4.6 深度主副武器升级卡牌与专精构建
- **主武器深度专精卡**：
  - 自动装填机与弹夹系统：如“大容量弹夹”、“快速整装弹链”、“强制两连发”。
  - 穿深与杀伤特化：如“贫铀穿甲弹芯”、“热压高爆破片”、“串联装药破甲战斗部”。
  - 极端战术改造：如电磁轨道炮的“过载脉冲”（牺牲射速换取全图瞬时穿透全高掩体）。
- **副武器与挂载强化卡**：
  - 导弹类：增强破甲深度、防空双用途、智能顶攻轨迹（Top-Attack）。
  - 战术布雷与部署物：磁性吸附地雷、高耐久自动防御哨塔、诱饵发烟器。
- **涉及系统**：`cards/*.json`、`tank_cards.js`。

### 4.7 画质表现增强与高清化贴图（Visual Overhaul）
- **高清贴图与资产重做**：
  - 摆脱简易几何拼接感，推进高分辨率 2D/2.5D 精品战车纹理（车体履带槽、反应装甲块、防滑涂层、炮盾帆布包裹、车灯与机枪细节）。
  - 地形纹理高清化：草地、碎石路、泥泞车辙、水波涟漪、雪地积雪的高精度烘焙。
- **战术特效与环境氛围升级**：
  - 高质感粒子渲染：火炮击发时剧烈的炮口冲击波扰动、地面扬尘、退壳烟雾、跳弹火花。
  - 损伤动态视觉化：车体被击中部位留下焦黑凹陷弹坑、反应装甲引爆后的残损外露、发动机受损冒黑烟与着火特效。
- **涉及系统**：`tank_assets.js`、`tank_battledraw.js`、`tank_fx.js`、`tank_paint.js`（**程序化烘焙为唯一实机路径**；后期贴图按 `docs/ASSETS-PIPELINE.md` 落盘）。伪 3D 的立体感强化方案见 `docs/specs/map/pseudo-3d-2p5d.md`（设计预留）。

### 4.8 短时战术闪跃模式（Tesla RCS 风格，取名「闪跃姿态 / Rapid Counter-maneuver Stance」）
- **机制设计**：
  - 按键激活后，坦克在短时间内（如 1~1.5 秒）触发反应控制系统（RCS，Rapid Counter-maneuver System），底盘瞬间轻微离地（短时起飞/悬浮），并沿输入方向以远高于正常极速的速度做一次急促闪避/穿越。
  - 闪跃期间车体处于**无敌/闪避状态**：可直接越过地雷、沙袋等低矮障碍，且对来袭炮弹/导弹的判定命中率大幅降低（相当于"躲开炮弹"）。
  - 闪跃后进入短暂冷却（如 6~10 秒），并伴随轻微发动机过热负面，防止无限连续位移。
- **视听反馈**：
  - 起飞瞬间伴随白色气流/离地尘土粒子，伴随电机/压缩空气释放声与短促推进器轰鸣。
  - 车体离地后绘制底盘反光与短暂阴影偏移，落地瞬间伴随轻微震屏与落地尘土。
- **适用载具**：优先赋予高机动轮式车辆（BTR、半人马、08 轮突）及"赛博/实验性重坦"特殊车型；可作为局内升级卡或车辆固有能力出现。
- **涉及系统**：`tank_move.js`、`tank_abilities.js`、`tank_physics.js`、`tank_rules.js`、`tank_fx.js`。

#### 6.1.1 ②a 的感知来源（为什么玩家会读成「上限被自动抬高」）

三条都可核实，都不是自动提速代码：

1. **公路加成把表速推过进度条满格**。`boostedMax = min(375, baseMax + roadBonus)`（`js/tank_move.js:113-115`）使读数超过 `tankKmh` 折算的条满，而 `spFill` 被 clamp 到 100%（`tank_battle.html:5302-5305`）⇒ 数字继续涨、条不再动，形似「上限被抬」。Boss 节点同样铺公路（路网无条件生成 `js/tank_nodegen.js:3692`；`js/tank_map.js:417-420` 只是 Boss 场禁用 strip 走廊）⇒「进 Boss 节点好像变快了」。
2. **HUD 文案低估一半**（#AA1）：标 +5、实机 +10，跳变看起来像额外机制。
3. **玩家主动触发的瞬时高速**被记成自动：`flash_dash speedMult = 2.5`（`js/tank_rules.js:302`）；超装填只改装填、不改速度（`:294-298`）。

⇒ **结论**：不存在自动提升极速上限的路径，本项**不立案**。若日后观察到「无公路、无闪跃」仍然更快，需新证据（坦克型号 + 节点类型 + `__TEST__` 速度读数或录屏）才重新立案。

### 6.3 电磁炮充能 / 放电音效（新能力；**先补 specs 口径，再写实现**）

**结构约束（决定实现形态，已实测）**：`SOUND_DEFS` **无法表达循环**——`_scheduleLayer` 对每层一次性 `start/stop`（`js/tank_audio.js:405`/`:407`/`:433`/`:442`，包络在 `end` 收敛到 0.0001）。⇒ 充能电流声必须由**代码驱动的持续实例**承担，不能只加一个音效键。现成范式 `startEngineSound`/`updateEnginePitch`（`:214-246`）**未被 `module.exports` 导出（`:604-617`）且全仓零调用**（死代码）。

**执行方案**：
1. **先写口径**：在 `docs/specs/combat/audio.md` 新增一节，定义三段式声学——① 充能上升电流（频率与增益随 `railChargeProgress` **单调上升**）② 就绪封顶（`railReady` 的高频保持/提示）③ 放电瞬态撕拉 + 炮身低腔余韵。数值唯一口径落 `RULES.railgunFx.audio`（视觉参数已在 `RULES.railgunFx`，`js/tank_fx.js:370-373`）。按 `AGENTS.md` §2.3 三步：主题页正文 → `docs/specs/combat.md` 兼容页**追加新编号**摘要 → `node scripts/wiki-check.js`。
2. **瞬态层**：新增 `railDischarge`（放电撕拉）；现有 `firerail` 保留为发射轰响或按裁定拆分，触发点沿用 `js/tank_fire.js:272`。
3. **循环层**：新增并**导出** `startRailChargeLoop()` / `updateRailChargePitch(progress)` / `stopRailChargeLoop()`（仿 engine 循环，含 AudioContext 缺失安全降级），接线两处——玩家侧 `railChargeProgress` 的非 0↔0 边沿（`js/tank_battledraw.js:145`，消费点 `:1747`）；Boss 侧 `railCharge`/`railReady`（`tank_battle.html:5074-5083`，把 `ui`/`pen` 换成充能循环 + 就绪提示）。
4. **顺手清账**：`startEngineSound` 死代码二选一——**接线**（引擎转速随 `t.speed` 变化，与制动同属机动域，建议同批裁定）或**删除**；文件头「12 类音效」注释改为实测键数。
