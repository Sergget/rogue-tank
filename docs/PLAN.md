## 3. 开发者面板改进方案（2026-09-16 提出，待用户裁定）

> **范围更新（2026-09-17）**：ISSUES #C5c 点名「开发者面板功能需要细化」且两页 UI/按键需统一——本方案与两页统一改造**合并裁定**；bench `#benchPanel` 的独有功能（无敌/秒装填/满血重置/清场/键位表）与 mvp `#devPanel` 的独有功能（散布归零/无视野/stats 覆盖/修饰器编辑/实时参数）需统一规划进 Tab 分页。

**现状问题**（`tank_mvp.html:411-483` #devPanel + `renderDevCards` :2117）：

- 卡牌选择是**单列 170+ 张平铺按钮**（9px 小字、无分组、无搜索、无持有关标注），找卡靠肉眼扫；
- 「已持有卡牌」区只读、与选择区无联动，无法在调试时清除单张卡牌效果；
- 全部区块（调试开关/数值/实时参数/解算/卡牌/修饰器）纵向平铺，高频区块（实时参数）与低频区块（调试开关）无主次，400px 宽单栏滚轮路径过长。

**改进方案（三块）**：

1. **卡牌选择器重构（用户点名需求）**：
   - **分类显示**：按效果类型分组为可折叠分区——主武器 install / 副武器 install / 武器 upgrade / 弹种 upgrade / 主动技能 / 被动(modifier) / 无人机 / 其他——分组头显示该组数量，默认全展开、支持折叠记忆；
   - **已持有标注**：持有的卡在列表项上显示 `×N` 角标（复用 `heldCardsVM`/`cardStackCount` 已有逻辑），稀有度色条沿用奖励页四色；
   - **可应用**：点击即 applyCardEffects（现有行为保留）；
   - **可清除卡牌效果**：新提供两种清除——(a) 每张持有卡行内「−1」按钮：回滚单张卡副作用（复用 #A24 卡牌事务 `snapshotCardTx`/`rollbackCardTx`，事务 receipt 已覆盖 modifiers/cardEffects/weapons/ammo/drones 五个副作用面，工程上已具备单卡回滚能力）；(b) 「清除全部卡牌」按钮走既有 `clearCardsFromTank`；
   - **搜索框**：按名称/标签实时过滤（170+ 张的可用性底线）。

2. **布局分层**：
   - 顶部改为 **Tab 分页**：`实时`（实时参数+发射解算，高频默认页）| `卡牌`（卡牌选择器+已持有）| `参数`（数值临时调整+修饰器）| `开关`（调试开关+重置）——替代单栏长滚动；
   - 面板宽度 400px→480px，分区标题统一小字距样式（现样式保留微调）。

3. **交互补强**：
   - 搜索框自动聚焦快捷键（面板打开时 `/`）；apply 成功后列表项短暂高亮反馈；
   - 「已持有」区与选择区合并进同一 Tab：持有行内提供 −1 / 清除，下方即全池分类列表，调试流「加一张→看效果→减一张」不换页。

**实现落点**：纯 DOM 层改动（`tank_mvp.html` 内联 + 可选下沉 `js/tank_panels_dom.js` 新增 `createCardPickerDom` 工厂供 bench 复用）；核心逻辑全部复用 `tank_panels_core.js` 既有事务函数，不新增状态面。Bench 的卡牌面板同步受益（可选第二批）。
