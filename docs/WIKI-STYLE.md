# Rogue Tank — Specs Wiki 风格规范（WIKI-STYLE）

> **本文件是全批 wiki 化的唯一规范权威**（2026-10-21 制定，样板卷 = `docs/specs/combat/`）。
> 其它四卷（map / cards / boss / editor）拆分时**必须**遵循本文；与本文冲突的临时约定一律作废。
> 流程纪律（文档分工、4 步生命周期）仍以根目录 `AGENTS.md` §2 为准；本文只约束 **specs 的形态与写法**。

---

## 1. 为什么要 wiki 化

`docs/specs/*.md` 原本是「单卷长文 + 按时间追加的批次章节」。单卷最长 900+ 行、同一主题散落 5~10 节，读者查一个机制要先跳三次。wiki 化把它拆成**一主题一页**，同时用**兼容索引页**保住 `§N` 这个外部契约。

三条不可动摇的约束：

1. **`§N` 编号是外部契约**：全仓 **600+ 处**引用 `docs/specs/<卷>.md §N`（2026-10-21 实测：五卷合计 548 处，其中 combat 单卷 245 处；含 `js/*.js` 注释、`AGENTS.md`、`DEVELOPMENT*.md`、归档分卷）。拆分**不得**改号、删号、重排号。
2. **内容不得丢失**：拆分是「搬家 + 重新分组」，不是「重写 + 摘要」。可以合并、可以拆细、可以改标题层级，但**结论、数值、脚注、沿革注记一个都不能少**。
3. **现行口径只能有一个家**：同一参数/数值/规则只允许在**一个页面**里写「当前值」，其它页面一律链接过去。沿革可以散落，现行值不行。

## 2. 目录结构与命名

```
docs/
├── README.md                     # docs 层总导航（四份主文档 + specs 的关系）
├── WIKI-STYLE.md                 # 本文件
├── DEVELOPMENT.md / PLAN.md / ISSUES.md / ARCHIVE.md
├── archive/                      # 归档正文（含 wiki 化前快照）
└── specs/
    ├── README.md                 # specs 总目录 = wiki 首页
    ├── combat.md                 # ★ §N 兼容索引页（不是正文）
    ├── map.md / cards.md / boss.md / editor.md   # 同上
    ├── combat/                   # ★ 正文分页
    │   ├── index.md              # 卷首页（必备）
    │   ├── changelog.md          # 沿革/已作废节（必备）
    │   ├── core-concepts.md
    │   ├── armor-ricochet.md
    │   └── ...
    ├── map/  cards/  boss/  editor/   # 结构同 combat/
```

**命名规则**

| 对象 | 规则 | 例 |
|---|---|---|
| 卷首页 | `<vol>/index.md` | `combat/index.md` |
| 沿革页 | `<vol>/changelog.md` | `combat/changelog.md` |
| 主题页 | 英文 **kebab-case** + `.md` | `ammo-system.md`、`enemy-scaling.md` |
| 页面标题（正文 h1） | **中文** | `# 弹种系统` |

- 文件名**只用小写英文、数字、连字符**；不用拼音、不用中文、不用下划线。
- 一个文件 = 一个主题。名字要能被猜中（`reload-fire.md` 优于 `misc-2.md`）。
- **不要**建 `part1.md` / `tmp.md` / `new.md` 这类无语义文件名。
- 页面数量参考：单卷 8~20 页。**少于 8 页**说明拆得不够；**多于 20 页**要检查是否出现了「一个函数一页」的碎片化。

**页面篇幅**

| 篇幅 | 处理 |
|---|---|
| < 15 行 | 太薄：并入相邻页，不单独成页 |
| 40~200 行 | 正常 |
| > 250 行 | 拆页，或检查是否混入了沿革/批次内容 |

```markdown
> **相关**：[装甲与跳弹](./armor-ricochet.md) · [曲射火力](./arc-fire.md) · [武器与装填](./weapons-reload.md)

## 目录
- [弹种升级链](#弹种升级链)
- [数值总表](#数值总表)
- [平衡回归](#平衡回归)

## 弹种升级链
……正文……

## 数值总表
……正文……

## 相关页面
- [装甲与跳弹](./armor-ricochet.md) — 跳弹角与等效厚度怎么用
- [曲射火力](./arc-fire.md) — 曲射弹种的越障契约
- [武器与装填](./weapons-reload.md) — 装填时长公式
```

**头部信息块四行，缺一不可**：

| 行 | 要求 |
|---|---|
| `**摘要**` | 一句话说「本页解决什么问题」，**≤60 字**，不要罗列目录 |
| `**适用版本**` | 三态之一：`现行（YYYY-MM-DD）` / `已作废（YYYY-MM-DD）` / `设计预留（未落地，YYYY-MM-DD）` |
| `**源自**` | 原单卷文件 + 原节号 + 拆分日期；跨卷合并写多个来源 |
| `**相关**` | 2~4 个同卷/跨卷页面，用 `[中文名](./file.md)`，`·` 分隔 |

**`## 目录`**：仅当页面有 **≥3 个 h2 正文标题**时必填（2 个及以下省略——实测 2 节页面加目录只是噪音）。目录条目用页内锚点，**不写 §N**。

> **实测校准（combat 卷，2026-10-21）**：`arc-fire.md`（2 节）、`camera-vision.md`（2 节）按此规则**不加目录**，阅读体验更好；`changelog.md`（9 节）加目录后从"翻不到"变成"扫一眼就能跳"。**结论：这条规则保留，不要为了"模板一致"给 2 节页面硬加目录。**

**`## 相关页面`**：必须放在**页面最末尾**（`## 沿革` 之后）。2~4 条，每条一句「为什么相关」，不要只丢链接。

> **模板示例说明**：本文中所有 `[xxx](./yyy.md)` 都是**格式示意**，目标文件不一定存在；链接检查脚本（§8 第 4 项）应跳过本文件。

**第三态「设计预留」的定义（2026-10-21 由 map 卷回写，样板卷只有两态）**

`现行` 与 `已作废` 覆盖不了第三类内容：**已写进规范、用户在具体日期裁定过、但代码尚未（完全）落地**的设计。它不是现行（不能当「现状」引用、不能据此写新代码），也不是作废（没有被推翻，实施时仍以此为准）。

| 判据 | 说明 |
|---|---|
| 何时用 | 该节同时满足：① 有用户/设计裁定与日期锚点；② 有明确目标语义与验收口径；③ 代码**部分或全部未落地**（含「设计预留」标注、`尚未接入` 字样、TODO 态 checklist） |
| `适用版本` 写法 | `设计预留（未落地，YYYY-MM-DD）`；**日期取裁定日**，不是拆分日 |
| 页面内要求 | 页头下方必须紧跟一个「落地状态」小表或一句话，逐子节标注 **已落地 / 未落地**（例：map 卷 §14 的 14.1/14.2/14.4 已落地、14.3/14.5/14.7 未落地）；混装父节**不得**整体标成一个状态 |
| 与 changelog 的关系 | **不进 `changelog.md`**——它还在等实施，不是历史。实现并三链验证后，按 AGENTS.md §2.2 把 `适用版本` 改成 `现行（落地日）` 并移除「未落地」标注 |
| 与 `§0` 主题索引的关系 | 「现行口径」列**不得**指向设计预留页；只能出现在「来源沿革」列，或单列一行「设计预留」。读者按现行口径查时不应命中未落地设计 |
| 兼容索引摘要 | 摘要须显式写「设计预留 / 未落地」，避免只看 `§N` 兼容页的人误以为已实现 |

> **为什么单独设一态而不是塞进「已作废」**：map 卷 §14 的失败模式不是「内容错了」，而是「读者以为它已经跑在游戏里」。`已作废` 会诱使后续 agent 删掉设计参数；`现行` 会诱使按未落地语义写测试。第三态把「等实施」这个事实显式化。

## 4. 链接语法

| 场景 | 写法 |
|---|---|
| 同卷内页面 | `[弹种系统](./ammo-system.md)` |
| 同卷内小节 | `[数值总表](./ammo-system.md#数值总表)` |
| 跨卷页面 | `[卡牌规范](../cards/index.md)` |
| 跨卷小节 | `[卡牌硬限](../cards/card-effects.md#硬限)` |
| 回到兼容索引 | `[§3.2 兼容条目](../combat.md#32-弹种数值总表)` |

**锚点规则（重要）**

- 锚点 = 目标页对应**标题文字**，空格换成 `-`，去掉 `（）`、`、`、`：`、`；` 等标点；英文保持原样。例：`## 数值总表` → `#数值总表`；`## 双联火炮（#E13）` → `#双联火炮e13`。
- **不要**用 `§N` 做页面内导航（`§N` 只用于溯源标注，如「（原 §3.2）」）。
- 链接**必须能在纯 Markdown 预览里点开**（相对路径，不以 `/` 开头，不带 `file://`）。
- 目标页不存在 = 拆分红线：迁移后必须跑链接检查（见 §8）。

## 5. 内容分层（wiki 的核心）

每个主题页按**固定顺序**组织：

1. **现行口径**（现在是怎么做的）——占页面主体 70% 以上。
2. **实现与约束**（代码入口、字段名、易错点、回归测试）。
3. **沿革**（可选）——只放「这一页涉及的」历史；跨页的大段历史放 `<vol>/changelog.md`。

规则：

- **现行与沿革不得混排**。历史内容一律在 `## 沿革` 之下，或整节搬到 `changelog.md`。
- **禁止同一数值在一页出现两次**；跨页重复同样禁止——一个数值只能有一个「家」，其它页写「见 [X](./x.md)」。
- **禁止无日期锚点的「本轮/本批/最近」**（AGENTS.md §2.1）。写 `2026-10-20 #W9` 或 `2026-10 月`。
- **页面必须能独立阅读**：不写「如上节所述」，改为复述一句或链接。
- 表格用于**参数/对照**，不用来排版散文；每张表上方一句「这张表回答什么」。

## 6. `§N` 兼容层（本方案的关键机制）

### 6.1 规则

- `docs/specs/<vol>.md` **保留不删**，改为「兼容索引页」。
- **保留全部 `## N.` 与 `### N.M` 标题文字与编号**（含 `3.2b` / `8.6b` / `14.1b` 这类带字母的编号），一个不增、一个不减、顺序不变。
- 每个标题下只留 **1~3 行摘要 + 链接**：

```markdown
### 3.2 弹种数值总表（用户 2026-09-13 权威表，已落地 `RULES.ammoTypes` per-ammo 字段）

> 14 个弹种的穿深/伤害/弹速/弹药架倍率/跳弹角/精度/未击穿，以及 HE 家族溅射半径与击退系数——**本卷唯一数值口径**。

**详见**：[弹种系统 · 数值总表](./combat/ammo-system.md#数值总表)
```

- `§0` 保留为**主题索引表**，但把「§X」换成指向 wiki 页的链接（`§N` 可留在括号里做溯源）。
- 兼容页顶部必须有固定警告块（见 §6.3）。

### 6.2 为什么这么做

- 读者/工具按 `combat.md §3.2` 跳进来 → 看到摘要 → 点「详见」进主题页，**引用永不 404**。
- 历史批次日志按「只增不改」维护，不能为了改链接去批量回改归档。
- `§N` 因此成为**稳定契约**，wiki 页是**内容载体**，二者解耦。

### 6.3 兼容页头部模板

```markdown
# 战斗与物理系统规范 —— 兼容索引（现行内容见 wiki 分页）

> ⚠️ **本页是 §N 兼容层**：全部章节编号原样保留（全仓 245 处外部引用依赖它们），
> 但正文已迁至 `docs/specs/combat/` 下的主题页。**查现行口径请点每节的「详见」链接。**
> 拆分日期 2026-10-21；拆分前单卷原文快照见 `docs/archive/2026-10-pre-wiki-combat.md`。
```

### 6.4 兼容页维护

- **新增章节**：仍按 `§N+1` 追加（编号只增不改），在兼容页加标题 + 摘要 + 详见，正文写进主题页。
- **改现行值**：只改主题页；兼容页摘要若含数值，必须同步（摘要尽量**不写具体数值**，只写「见 X」）。
- **作废某节**：标题保留，摘要行改成「已被 §Y 取代」，详见指向 `changelog.md` 对应锚点。

## 7. 迁移规则（拆分时照做）

1. **先存快照**：把待拆分的单卷原文完整存到 `docs/archive/<yyyy-mm>-pre-wiki-<vol>.md`，文件头写「拆分前快照 + 日期 + 行数 + SHA256」。
2. **先建页面骨架，再搬正文**：每页先写头部块 + 一级标题骨架，再逐节粘贴原文，避免边搬边改结构。
3. **原文优先原样搬运**：只允许改标题层级、加导航、拆并小节；**不允许**在搬运时顺手改结论/改数值/删「沿革」注记。需要改写时另开一次提交并在报告里说明。
4. **一节拆多页**：在该节标题下写「本节拆为 A / B」，两页各自头部 `源自` 都写该节号。
5. **多节合页**：页面内按原节顺序排列，每个 h2 标注 `（原 §X）`。
6. **每页收尾**：补 `## 相关页面`（2~4 条）与 `## 目录`（≥3 h2 时）。
7. **建兼容索引页**：按 §6.3 重写单卷文件，**逐条保留编号**。
8. **跑验收脚本**（§8），LOST 必须为 `[]`。

## 7.5 拆分判定的五条经验（2026-10-21 combat 卷实测）

这一节是**实战校准**：combat 卷拆分时踩到的判断点，map / cards / boss / editor 照做可以少返工。

### ① 「现行 / 作废」要按**子节**判，不能按**父节**判

`combat.md §11` 的标题写着「现行口径」，但它下面：`§11.1` 已作废、`§11.2` 是纯沿革、`§11.3` **仍然现行**。按父节整体搬进 changelog 会把 §11.3 的 Boss 激光口径一起埋掉。

**规则**：迁移前对**每个 `### N.M`** 单独判定状态（现行 / 作废 / 混合），父节标题不可作为依据。混合父节在兼容索引里只写一句「§11.1/§11.4/§11.5 已作废，§11.3 仍现行」并给两个链接。

### ② 「< 15 行就并页」要按**主题**并，不能按**行数**并

combat 里有几个 3~6 行的小节（如 §8.6 神话稀有度、§8.4 HE 击退、§12.2 光束截断），单独成页太薄，但它们各自的**主题归属很明确**：§8.6 → 武器与装填（稀有度是武器安装的一部分）；§8.4 → 弹种系统（溅射/击退是弹种属性）；§12.2 → Boss 战斗。

**规则**：并页时看「读者会去哪个主题页找它」，而不是看「和哪一节挨着」。并进去后在页面内保留 `（原 §8.6）` 标注。

### ③ 一个原节可以被**两页**引用，但只能有**一页**写正文

`§5`（AI 触发）同时被 `enemy-ai.md`（触发机制）和 `enemy-scaling.md`（难度分化）引用；`§6`（特效）同时被 `fx-visual.md`（绘制规范）和 `hud-ui.md`（装填环/HUD 段）引用。

**规则**：正文只放一页；另一页在页首 `源自` 里也写该节号（表示「本节有我关心的部分」），但正文只写自己那一段 + 链接过去。这样「节 → 页」映射表不会出现"两页都完整转载"的重复。

### ④ 批次页（§8~§14）拆分时，页面归属看**内容**不看**批次**

`§9.5` 在「#G 批次」里，但它的两半分别属于 Boss 战斗（激光转速）和 Boss 战斗（召唤波次）——同一页；`§13.6` 一半是部署物（地雷上限）、一半是武器（换装重置），**必须拆到两页**。

**规则**：一个 `### N.M` 内部若含两个不相干主题，允许按内容拆成两段分放两页，两页都在 `源自` 写该节号，并在段首标 `（原 §13.6 前半）`。

### ⑤ 兼容索引页会变长，这是**预期**，不是失败

`combat.md` 从 900 行正文缩到 418 行摘要，但仍是全卷第二长的文件。**这是设计**：它是 63 个标题的目录 + 每节 1~3 行摘要。不要为了提高「压缩比」把摘要删到一行——摘要太短，读 `§N` 引用的人看不出该不该点进去。

**规则**：兼容页摘要保持 **1~3 行、且必须说清「这节讲什么 + 有什么约束」**；不要写「见 wiki」四个字了事。

**实测标定（2026-10-21 map 卷追加）**：兼容页行数 ≈ **6.3~6.6 行/标题**属正常（combat 63 标题 → 418 行 = 6.6；map 119 标题 → 751 行 = 6.3）。若某卷 >900 行，说明标题数已超 140，应考虑**分卷**而非压缩摘要。

### ⑥ 一个父节拆到两页时，兼容索引的父节摘要要**显式分叉**

map 卷有 3 处「父节标题与内容主题不符」的典型：`§12`（标题讲掩体收敛，但 `§12.3~12.5` 是路网 v3 / 沿路建筑 / 校准重锚）、`§14`（标题讲 strip 设计预留，但 `§14.1/14.2/14.4` 已落地）、`§5.4`（标题「其他需补充内容」，实为 TODO 清单）。

**规则**：兼容索引里该父节摘要写成「**混合章节**：`§12.3~12.5` 见 [路网](./map/roads.md)，其余见 [掩体](./map/cover-system.md)」并给**两个**详见链接。**不要**把父节摘要只指向其中一页——那会让读兼容页的人以为另一部分消失了。

### ⑦ 一页混装多种状态时，`适用版本` 这样写

map 的 `strip-defense.md` 同时含「现行」（防线式推进，B 档已落地）与「设计预留」（§14 横向卷轴未落地）两种状态。

**合法写法**：`**适用版本**：现行（2026-10-21）；§14 部分为 设计预留（未落地，2026-09-21）`
**规则**：主状态在前、例外在后，用 `；§N 部分为 …` 分隔。**不要**为了单一值而把混合页拆开（那会产生大量 <15 行的碎片页）。

### ⑧ 「批次章节」的判定标准与三类边界

按「标题含日期锚点（`YYYY-MM-DD`）或批次号（`#X`）」判定，map 的 27 节中 22 节符合。但有三类**边界情况**：

| 边界情况 | 处理 |
|---|---|
| 标题写现行口径、内容含大量批次沿革（如 map `§1`/`§17`/`§25`） | **按子节判**（见 ①），父节标题不作为依据 |
| 「主题归并视图」型（如 map `§28`） | **不单独成页**，吸进 `<vol>/index.md`（否则会有两个导航页） |
| TODO checklist（如 map `§5.4`） | 放 `<vol>/changelog.md` 的「未落地」区，**不要**混进现行主题页 |

### ⑨ 小卷（<300 行）的页数下限由**主题密度**决定，不由行数决定

cards / boss / editor 三卷合计仅 822 行，按行数直觉会想压到 6 页；实测最终 **11 / 9 / 9 页**（2026-10-21）。三个页数上调的直接原因都是「**单页会同时违反两条规范**」：

| 卷 | 初判 | 实际 | 触发上调的节 | 违反的规范 |
|---|---|---|---|---|
| cards | 8 | **11** | `§8`（**102 行 / 5 子节**，其中 `§8.3` 机制卡 35 行） | 「> 250 行拆页」+「一个文件 = 一个主题」（设计契约 vs 武器卡清单） |
| boss | 7 | **9** | `§5`（含 `RULES.boss.tuning` **10 键真值表**） | 「现行口径只能有一个家」——数值表埋在行为页里会让高频入口找不到家 |
| editor | 6 | **9** | `§7`（**88 行 / 7 子节**，`§7.5` 浏览器四链与面板无关） | 「一个文件 = 一个主题」（面板体系 vs 测试基础设施） |

**规则**：判断「该不该独立成页」看**三条**——① 读者会不会**单独来查**它（如「查 `RULES.boss.tuning`」）；② 它含不含**唯一口径**表（含则必须独立，否则违反「一个家」）；③ 和同页其它内容**主题跨度**是否超过一层（如「面板布局」vs「浏览器测试链」）。

> **反例**：`editor/browser-tests.md` 仅 44 行、`boss/runtime.md` 仅 30 行——按「< 15 行太薄」都不该拆，但按上面三条它们**都必须独立**（读者会单独来查「四链怎么跑」/「运行时三件套是哪几个」）。**篇幅不是唯一判据。**

### ⑩ 拆分前必须先做「token 基线」，否则「内容零丢失」无法自证

三卷拆分时用**标识符级比对**验证「内容不丢失」：从原文抽出全部 **≥4 字符英文标识符**（如 `getMultForKey` / `RULES` / `weakspots`）与**全部数字**（含小数，如 `0.7000` / `99999`），然后校验这些 token **是否出现在「兼容页 + 全部 wiki 页」的合并语料**里。实测基线：

| 卷 | 标识符 | 数字 | 拆分后缺失 |
|---|---|---|---|
| cards | 509 | 169 | **0 / 0** |
| boss | 342 | 135 | **0 / 0** |
| editor | 379 | 106 | **0 / 0** |

**规则**：这套比对能抓出「概括性改写导致的细节丢失」（例如把「`ammoMult=2` / `crewMult=1.5`」简写成「按弹种表值」就会丢掉两个数字）。**做拆分前先把基线存成 JSON**（`tmp/wiki-baseline.json`），拆完后再跑一次比对；缺失不为 0 就说明有内容被压缩掉了。

> **注意**：token 比对无法发现「语义错位」（数字还在但挂错了节），那需要靠**节→页映射表**人工抽查。两者互补，都要做。

## 8. 验收清单（每次拆分后必跑）

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 编号集合 | 拆分前 `## N.` + `### N.M` 集合 与 兼容页标题集合 **完全相等**（`LOST=[]`、`EXTRA=[]`） |
| 2 | 编号顺序 | 兼容页标题顺序 = 原顺序 |
| 3 | 内容覆盖 | 每个原节在「节 → 页」映射表里都有目标页；每页 `源自` 覆盖其承载的节号 |
| 4 | 链接可达 | 所有 `](./`、`](../` 目标文件存在；页内锚点在目标页有对应标题 |
| 5 | 模板完整 | 每页有 摘要/适用版本/源自/相关 四行 + 末尾 `## 相关页面` |
| 6 | 数值唯一 | 同一参数名在**全卷**只出现一次「= 值」形式 |
| 7 | 沿革隔离 | 现行页无「已被 X 取代」的整段正文（只允许一行指路） |
| 8 | 全局链 | `node scripts/check-html.js` EXIT=0（docs 不被扫描，用于确认没碰坏其它） |

**参考实现**：`docs/specs/combat/`（样板卷）。任何与本规范不一致之处，以本规范为准并回改样板。

## 9. 与既有文档纪律的关系

| 既有规则 | 在 wiki 下的落法 |
|---|---|
| 现行细则只写 `docs/specs/<system>.md`（AGENTS.md §2.1） | 现行细则写 `docs/specs/<system>/<page>.md`；兼容索引页只放摘要与指针，**不再承载正文** |
| 被推翻的设计不静默删除 | 原文进 `<vol>/changelog.md` 或页内 `## 沿革`，保留 `~~删除线~~` 与「已被 §X 取代」 |
| 同文档禁止重复罗列数值 | 全卷范围内一个数值一个家；其它页写链接 |
| 统计数字必须实测并标日期 | 页内统计写「（YYYY-MM-DD 实测）」；兼容页摘要不写统计 |
| 模糊词禁用 | 同左 |
| `§N` 不得重排（AGENTS.md §2.1 新增条） | 由兼容索引页承担；wiki 页内只作溯源标注 |

## 10. 反例（不要这样写）

- ❌ 主题页里贴 200 行历史批次日志 —— 应该进 `changelog.md`。
- ❌ 兼容页每个标题下保留完整原文 —— 那就不是索引页了，拆分失去意义。
- ❌ 两页同时写「装填硬限 = 1s」 —— 第二处应为「见 [装填](./weapons-reload.md#装填时长公式)」。
- ❌ `[点这里](combat/ammo-system.md)` 在 `docs/specs/combat.md` 里少了 `./` 前缀 —— 相对路径要相对**当前文件**。
- ❌ 用 `§3.2` 当页内跳转 —— `§N` 只做溯源。
- ❌ 页面没有 `## 相关页面`，读者走进死胡同。
