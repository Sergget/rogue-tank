# 友军指挥与战术协同

> **摘要**：单机少量 AI 友军的六命令、目标权威、状态反馈与导航验收；A0 命令闭环已落地。
> **适用版本**：A0 已落地（2026-10-27）；A1～A3 设计预留
> **源自**：2026-10-26 用户裁定「多人合作暂不考虑，少量友军和友军命令系统」；`docs/specs/combat.md` §16（新建）
> **相关**：[敌方 AI](./enemy-ai.md) · [HUD 与界面](./hud-ui.md) · [渲染路线](../map/rendering-roadmap.md) · [浏览器测试链](../editor/browser-tests.md)

| 子项 | 状态 | 说明 |
|---|---|---|
| 单机与少量友军方向 | **已裁定** | 不做本地/在线多人；首个切片设计容量为 2～4 辆友军，最终数量由战斗与性能实测决定 |
| 六命令与指挥 UX | **A0 已落地** | `focus / move / follow / hold / retreat / flank` + Z/X/H/R/V 键位；命令环（A2）未做 |
| 目标与任务协调 | **A0 已落地** | 新增纯逻辑任务层 `js/tank_ally_command.js`；决策与击发读同一权威目标 |
| 职能、导航与协同构筑 | **设计预留** | 在命令闭环后分批实施，不以增加人数替代行为质量 |

## 1. 目标与现状边界

目标是在**不中断玩家驾驶、瞄准与开火**的前提下，让少量友军执行可理解的战术意图。参考即时战术命令的「指目标、给意图、看反馈」，不把车战变成逐车 RTS 微操。

2026-10-26 实测边界：

- `tank_battle.html` 的非玩家实体统一经 `aiDecide` 与 `driveTank`；友军自主索敌，但开火目标仍由 `nearestEnemyTo(e)` 现取。因此仅在 AI 输出里加目标字段不足以实现集火，**决策与击发必须读同一个权威目标**。
- `js/tank_ai_squad.js` 的 `updateSquad` 只向 `enemies` 分配 `press/flank/hold`，是敌军协调器，不是友军命令系统。
- 现有友军可复用实体、武器、伤害、AI 和节点流程；本设计不另造友军伤害/命中规则，不引入网络同步。

## 2. 首版六命令

| runtime 命令 | 玩家意图 | 执行语义 | 终止/替换 |
|---|---|---|---|
| `focus` | 集火指定敌人 | 选择可行射界与交战距离，优先射击该目标；无射界时移动/报告，不默默改打最近敌人 | 目标死亡、命令替换、撤退；目标丢失转最后已知位置并报告 |
| `move` | 前往/占领指定区域 | 前往区域并分散占位，保留自主瞄准与反击；到达后转区域驻守 | 新移动/跟随/撤退命令 |
| `follow` | 跟随/护卫玩家 | 保持职能间距和射界，优先护卫而非贴车尾；自主攻击威胁 | 任意区域或目标命令 |
| `hold` | 驻守/防御区域 | 以锚点为中心选位、控制交战距离；可短程规避但不擅自弃点 | 新命令；危险规避后返回锚点 |
| `retreat` | 撤退/重组 | 解除 `focus` 与驻守约束，向玩家或明确集结点脱离；允许必要自卫 | 到达并稳定后转 `follow`，或由玩家另下令 |
| `flank` | 向指定目标侧翼迂回 | 经侧向阶段点进入可攻击位置；不以直线穿火网冒充迂回 | 到位转 `focus`，或命令替换/不可达 |

**默认快捷映射**：敌人 + 命令键 = `focus`；地面 + 命令键 = `move`；无目标/自身 = `follow`。`hold / retreat / flank` 由命令环或独立快捷键进入。具体按键由 `tank_bindings.js` 的唯一数据源在实施时分配，本文不预写死键值。

## 3. 控制层级、任务与优先级

- **控制层级**：全体、单车为 A0 必需；按职能编组属于后续 UX 扩展，不作为命令闭环前置。
- **任务快照**：每辆友军持有 `{order, issuer, targetId?, anchor?, issuedAt, phase, reason}`；实体死亡/节点切换/读档时按生命周期清理或恢复，禁止跨节点悬挂旧目标。
- **执行优先级**：防即死与防卡死的**局部反射** → 玩家直接命令 → 职能默认行为 → 自主交战。
- **局部反射边界**：允许短程躲爆炸、火焰、致命水域和解堵；不得以低血量、自主找掩体或换目标为由长期取消命令。偏离后须返回任务，确实失败才进入阻塞报告。
- **打带跑**：移动、驻守与撤退期间仍按武器射界、装填与职能决定开火；命令不是「只移动」开关。
- **友军非无敌**：伤害、模块、隐蔽、烟幕与地形沿用现有规则；是否允许被玩家复活/修理属于后续经济裁定。

### 3.1 统一目标权威

实施时新增纯逻辑任务/协调层（候选 `js/tank_ally_command.js`，最终命名随模块边界确认），其职责：

1. 把玩家命令解析为不可歧义的任务快照，校验目标存活、敌我、区域与可达性；
2. 为每辆友军分配目标、锚点与阶段，不与敌军 `updateSquad` 共用会串状态的全局缓存；
3. 向 `aiDecide` 注入任务上下文，输出机动与炮塔意图；
4. 向击发入口提供同一个 `targetId`/目标实体，替换友军击发时无条件 `nearestEnemyTo` 的绕行；
5. 在目标死亡、撤退、节点清理时显式失效，禁止保留悬空实体引用。

**写域**：AI/任务状态与 `RULES` 由 role-systems；武器击发契约如需修改由 role-combat 协调；HUD/命令环由对应页面唯一写者接入。不能三个角色同时改 `tank_battle.html`。

## 4. 输入与反馈

### 4.1 操作

- 短按执行上下文默认命令；长按/独立键打开命令环选择精确命令。
- 世界内目的地、侧翼路径与目标标记只在需要时短暂显示，避免常驻遮挡战场。
- 首版**不默认战术暂停或慢动作**。若实测驾驶中无法可靠操作，再单独评估轻度减速并补输入/模拟一致性测试。
- 命令输入从动作层抽象，键鼠与手柄共用；不得在 UI 层直接写友军坐标或目标。

### 4.2 可读状态

| 状态 | 玩家必须读到 |
|---|---|
| 已接受 | 谁接受、执行什么；头像/车旁图标 + 简短确认音/语音 |
| 执行中 | 前往、驻守、迂回、撤退等阶段；不刷屏、不每帧播语音 |
| 受限 | 无射界、被压制、路径暂堵；区分「仍在尝试」与「已失败」 |
| 失败 | 不可达、目标失效等具体原因，并给可操作的取消/重下指令 |
| 完成 | 到达目的地或完成集结，转入何种后续状态 |

语音承担信息反馈，按「受击/致命危险 > 命令失败 > 接敌 > 常规确认」限流。六命令的默认语义必须在 HUD 可发现，不依赖玩家背文档。

## 5. 职能、导航与构筑扩展

| 工作包 | 边界 |
|---|---|
| 前卫/重甲 | 卡路口与承受压力；仍受玩家撤退/驻守命令约束 |
| 侦察/轻甲 | 点灯、标记、侧袭；不得变成永久最优万能车 |
| 火力支援 | 自走炮/导弹依赖射界或友军视野，与现有曲射/锁定契约一致 |
| 保障/工程 | 修理、烟幕、部署掩体，A0 后再裁定资源与冷却 |
| 导航 | 编队间距、窄路让行、替代路径、动态破坏后的重寻路、避水避火与撤退通道 |
| 构筑 | 指挥响应、协同标记、维修/补给、烟幕/交叉火力等；禁止只堆友军血伤 |

遭遇可设计守点、夹击与反伏击来让命令有意义，但**不得让大部分节点退化为护送脆弱 NPC**。友军强度、击杀得分与补给需一起校准，避免抢光成长资源或成为免费消耗品。

## 5.1 A0 落地口径（2026-10-27）

### 模块与数据

- **唯一逻辑入口**：`js/tank_ally_command.js`（纯逻辑、Node 可测、无 DOM）。
- **任务快照**：每辆友军持有 `_allyOrder = {order, issuer, targetId, anchor, issuedAt, phase, reason}`；`phase ∈ moving / holding / flanking / retreating / blocked`。
- **目标权威**：`allyFireTargetFor(ally, ctx)`。`focus` / `flank` 只认任务目标，目标死亡即返回 `null`——**不暗换最近敌人**；其余命令允许在 `RULES.allyCommand.autoEngageRange` 内自主反击。
- **决策**：`aiDecide` 对 `team==='ally'` 且有任务时调用 `allyCommandDecide`，输出与 `aiDecideAlly` 同形；随后仍叠加 `applyWaterAvoidance`（友军不为命令豁免地形）。
- **状态机**：`updateAllyOrder` 处理到达转驻守、撤退完成转跟随、侧袭到位转集火、目标丢失 `blocked/target-lost`、长时间无位移 `blocked/stuck`。
- **编队规格**：`allySquadSpecs(node, mode, cfg)` 由 battle 与 `tank_3d.html` 共用。

### 配置（`RULES.allyCommand`）

`enabled` / `maxAllies` / `arriveRadius` / `formationSpacing` / `autoEngageRange` / `focusBand` / `flankOffset` / `stuckSeconds` / `stuckSpeed` / `retreatRange` / `aimTolerance` / `countByMode` / `allyTankId`。数量按模式：standard 2 / survival 2 / boss 1；友军坦克 `panzer-IV`。

### 输入（`js/tank_bindings.js` 唯一数据源）

| 键 | 命令 | 语义 |
|---|---|---|
| `Z` | 全体上下文命令 | 光标敌人 → `focus`；地面 → `move`；自身/空 → `follow` |
| `X` | 单车上下文命令 | 同上，目标为离光标最近的友军 |
| `H` | 全体驻守 | 锚点 = 光标地面 |
| `R` | 全体撤退 | 集结到玩家位置 |
| `V` | 全体侧袭 | 光标敌人；到位后自动转 `focus` |

### 反馈与生命周期

- HUD：左下 `#allyHud` 列出每辆友军的命令/阶段；命令接受/拒绝/受阻走 2 秒 `#allyToast` + 日志。
- 世界标记：锚点圆环+十字、集火目标红圈、车顶命令字标（`drawAllyOrderMarkers`）。
- 节点切换时 `clearAllAllyOrders` 并重新生成编队；任务不跨节点悬挂。
- 友军与据点（`outpost_*`）区分：`isAllySquad` 标记，结算加成只认据点。

### 已知边界（A1/A2 处理）

- 敌军 AI 仍只把玩家当主目标，友军暂不承担「被集火」压力。
- 无命令环/手柄动作层（A2）；无职能编队与导航让行（A1）。
- 不做逐车 RTS 微操、战术暂停与多人共享命令。

### 验证

`node scripts/test-ally-command.js`（快照/校验/目标权威/状态机/决策/编队规格）+ `node scripts/test-browser-ally.cjs`（生成/键位/集火权威/目标死亡/撤退/HUD）。

## 6. 验收与回归

### 6.1 A0 必过场景

1. **完整战术链**：跟随推进 → 指定非最近的重甲目标集火 → 两车驻守 → 残血车撤退 → 重组；目标选择与击发目标一致。
2. **替换语义**：`retreat` 能解除 `focus`；`move` 能解除 `hold`；新命令不叠加旧任务。
3. **不可达**：目标在致命水域/封闭建筑/地图外时明确失败或选替代路径，不原地抖动、不谎报执行。
4. **射界与自主交战**：`focus` 无射界时移位或报告，不暗换最近敌人；`move/follow` 可自主反击且不偏离任务。
5. **防卡死**：多车窄路、交叉让行、玩家堵路、动态残骸后有界时间内脱困或报告；不持续相互推挤。
6. **生命周期**：死亡、节点切换、重开与读档清理任务；存档恢复不产生重复友军或悬空目标。
7. **UX**：六命令可发现/取消；全体与单车均可用手柄动作层表达；失败原因在 2 秒内可读。
8. **性能与确定性**：固定 seed + 命令输入回放可复现目标/伤害/位置；命令评估有节拍预算，不逐车逐帧全图搜索。

### 6.2 测试分层

- 纯 Node：命令转移、目标权威、优先级、失效条件、队形/评分与不可达；固定 seed 负向断言。
- 浏览器：鼠标拾取、命令环、HUD 状态、驾驶中发令、目标死亡/撤退；覆盖键盘与手柄动作层。
- 场景 soak：多 seed、多地形与动态破坏；记录堵路、任务超时和友军输出占比，不能只测「不抛异常」。

## 7. 明确不在首版范围

- 本地/在线多人、网络同步、房间和共享命令；
- 直接驾驶友军、无限友军、复杂队形编辑、逐车技能微操；
- 把敌人 `press/flank/hold` 三角色改名后当作完整指挥系统；
- 通过让友军免疫伤害、必中或无视掩体来掩盖导航与射界缺陷。
