## 类型专属内容结构（现行，2026-11-03）

> 本节的数值与行为是 **2026-11-03 代码实测**结果（M3-J 结构批，见 `DEVELOPMENT-batches-2026-11.md` §4.212），**可直接当现行口径引用**；仍受 `RULES.nodeKinds.enabled` 总开关约束（默认 `false`）。参数标注 `[PLACEHOLDER]` 的部分待 M3-J 校准落值。

**要解决的问题**：类型原先只是 `node.kind` 标签 + 胜利判定分支，地图生成器（`generateNode` / `generateStrip` / 路网 v4）一处都不读 kind ⇒ defend / capture / breakthrough 与 exterminate **同图同内容**，类型差异只剩 HUD 文案与结算百分比——「换个名字的歼灭」。

**实现分工**（三层，写域不交叉）：

| 层 | 文件 | 职责 |
|---|---|---|
| 纯几何与目标选择 | `js/tank_objectives.js` | `planDefendObjective` / `planGuardRing` / `planCapturePoints` / `planBreakthroughChannel` / `coverBlocksChannel` / `pickEngageTarget` / `guardTargetAsEntity` / `objectiveBiasFor`；零 DOM、零 `entities` 依赖，可 Node 测试 |
| 生成期落图 | `js/tank_map.js` | `computeNodeKind` + `planNodeKindGeometry` 在 `makeNode` 内建结构；`applyNodeKindGeometry` 在 `applyRunKinds` 之后**重规划**（突破置中段/非战斗替换发生在生成后，不重规划则该节点永远没有结构） |
| 运行期消费 | `tank_battle.html` | 守点实体与占领圈取 `currentNode.typeObjective`；每帧按类型算 `engageBias` 并注入 AI 目标选择 |

### 防御：守点护墙环（几何涌现的「数个方向可打」）

- **守点位置**：从「最后一个防御点（敌人纵深）」改为 **出生点→首道防线之间 `xProgress=0.45` 处**，y 按 seed 确定性偏移 ±18% 地图高。
  改前的问题：玩家要穿过全部防线才看见自己要守的点，且波次刷怪锚点就在那些防御点上 ⇒ 敌人直接生在自己的目标上、护墙环被从内部绕过。
- **护墙环**：环心即守点，`radius 300`、径向厚 `70`、`gaps 3`、`gapWidth 150`、`blockLen 120`，tier **`intact`**（不可摧毁、`height 8`、`mode='solid'` 真拦弹）。
  **tier 不能取 `wall` / `perm_block`**：这两者 `shellBlock` 是 `'wall'`/`'solid'` 字符串但派生出的 `mode` 是 `'none'`，`stepShells` 只在 `mode==='solid'||'single'` 时截停炮弹 ⇒ 用它们做护墙会变成**纯装饰**（实测确认）。
- **「只能数个方向命中」是几何涌现，代码里没有任何远近特判**：弹道是直线 OP，过半径 R 处方位角恒等于发射角 θ，故能否命中只取决于 θ 是否落在缺口扇区内 ⇒ 可打方向恒为 3 个固定扇区。
  实测（12 块 intact，环心 5000,5000）：**可命中方位占比恒 20.1%**，D=400~4000 七档采样全部相同。
- **「近处更易击中」同样是几何涌现**：缺口横向容差恒为 `gapWidth/2=75px`，但方位角容差 `= atan(75/D)` ⇒ 距离越大容差越小。
  实测瞄准容差：D=350 `±10.7°` / 400 `±9.35°` / 600 `±6.22°` / 900 `±4.14°` / 1400 `±2.66°` / 2000 `±1.86°` / 2800 `±1.29°` / 4000 `±0.87°`，严格单调收窄。
- **敌人不会被封在环内**：波次刷怪锚点→环心最小距离实测 **539px**（5 seed × 70 锚点 = 350 样本），环外沿 `300+35=335` ⇒ 0 个敌人生在环内。
- 结构块带标记 `guardRing:true`，供 `applyNodeKindGeometry` 在节点类型被改写时精确摘除（不按 tier 摘——`intact` 被楼房与防御墙复用）。

### 占领：占领点脱离防线

- 点数按 `RULES.nodeKinds.capture.pointsMin/pointsMax`（2~3）+ seed 确定性抽取；x 均布于地图 `30%~86%`，y 在 `0.24/0.76` 两个高度带**锯齿散开**（带 ±5% 抖动）。
- 改前的死结：占领圈直接复用 `anchorGroups[i]`（防线锚点），与「逐个突破防线」在空间上完全重合 ⇒ 占领节点＝换皮歼灭。现占领点与防线 bucket 中心**不重合**（有负向断言锁住）。
- `captureTotal` 必须与**实际生成的圈数**同步：胜利判据是 `captureDone >= captureTotal`，而 `captureTotal` 原按「防御点组数 ∩ pointsMax」算、圈数按 2~3 抽样，两者不等时 ⇒ 永远无法达成（已改为以圈数为准）。

### 突破：通道净空

- 直通道沿玩家出生点 y 轴延伸到出口，净宽 `340`，两侧补 `intact` 墙（`wallThickness 60`，标记 `channelWall:true`）；通道内所有阻挡型掩体（`passability===0` 或有 `shellBlock`）被清除。
- 实测三个 seed：通道内残留阻挡物 **0**、两侧墙 **2**；敌人被推出新结构后与墙体重叠检查 `stuck 0`。

### 敌方目标欲望（按类型分档）

- `RULES.nodeKinds.engage`：`defendBias 0.82` / `captureBias 0.35` / `otherBias 0` / `distanceFalloff 900`。
- 打分 `score = bias × 1/(1+d/falloff)`，玩家与守点同台竞争；**`bias<=0` 直接短路返回玩家**⇒ `otherBias:0` 的类型（歼灭/突破/非战斗）与改前逐字段一致（零回归）。
- 生效链路：页面每帧算 `engageTarget` → `js/tank_ai.js` 的 `aiDecideEnemy` 以 `ctx.engageTarget || ctx.player` 作为唯一目标变量（`p`）⇒ 追击/绕后/炮塔朝向/`lastKnownPlayerPos` 全链路换目标；开火分支读**同一个** `engageTarget`，避免「炮塔朝 A、炮弹飞 B」。
- **守点被毁后必须回落玩家**：`guardTarget.hp<=0` 时不再参与打分（否则 AI 会对着废墟开火）。
- 实现要点：`objectiveBiasFor(kind, cfg)` 必须同时接受**整份 `RULES`** 与 `RULES.nodeKinds` 子段两种入参——页面传的是整份 `RULES`，只认子段的实现会恒返回 0（曾出现：单测传子段全绿、生产恒 0 的静默失效，现由负向断言锁住）。

#### 守点作为实体掩体必须豁免「自遮挡视线」（2026-11-19 修正，§4.216）

守点是运行时构造的 `tier:'intact'` 实体覆盖物（`height 8`、`vision true`），**它自己会挡视线**。AI 的开火前置 `ctx.hasLoS(敌.x, 敌.y, 目标.x, 目标.y)` 的射线终点就落在守点体内 ⇒ `findCoversOnPath` 必然命中守点本身 ⇒ `los` 恒 `false` ⇒ `canFire` 恒假。更糟的是目标变量 `p` 已被换成守点，所以这类敌人**连玩家也不打**，退化成只移动的哑炮。

**实测（seed 20261119，`scripts/measure-encounter-real.cjs`）**：修复前 `losProbe` 57 条样本 · 守点可见 **0** 次 · 敌方开火 **0** 发；修复后 90 条样本守点可见 **90** 次 · 敌方开火 5 发**全部打守点**。

**修法（两处）**：

1. `hasLineOfSight(ox,oy,tx,ty,coversList,opts)` 新增 `opts.ignore`——被瞄准的实体掩体自身不得遮挡射向它自己的视线（`js/tank_cover.js`）。**⚠ 不能无条件忽略**：只在射线终点确实落在该掩体体内时由调用方传入，否则打玩家时也会穿守点。
2. `js/tank_ai.js` 的 `_losOptsFor(target, tz)` 助手从 `target.hurtbox` 自动取 `ignore`，**全部 4 个 `ctx.hasLoS` 调用点**（`_passiveDefend` / skirmish / charge / 主 LoS 评估）统一改用它。

回归断言在 `scripts/test-covers.js` §31b：不带 `ignore` **必须**被挡（锁住病灶语义）、带 `ignore` **必须**通（锁住修复）、射线穿同一掩体去打别处**仍被挡**（锁住「不是全局穿透」）。

#### 守点耐久按波次火力定，不按掩体三发定（2026-11-19 校准，§4.216）

守点原借用 `RULES.coverTiers.building.hp`（= **3 发**），实测 **W1 开打 8 秒即被打爆**——defend 节点在玩家反应过来之前就判失败，任务语义不成立。现改由 `RULES.nodeKinds.defend.guardHp` 独立配置，由 `tank_battle.html` 的 `spawnGuardTarget` 读取，缺省才回落 `tier.hp`。

**现行值 `guardHp = 60`（2026-11-19 定案，§4.217）**。换算关系：守点每被炮弹命中一次扣 **1 点**耐久（`js/tank_fire.js` 的掩体命中分支调 `dmgCover(cover,1,'shell')`；`js/tank_cover.js` 的 `damageCover` 只在 `hp` 非有限值时短路）。实测**单波累计火力 ≈ 17~18 发** ⇒ 3 波 ≈ 51~54、4 波 ≈ 68~72。取 60 的判据是「放着不管第 3~4 波之间被打穿，玩家回防就能救下」；30（第一波必爆）与 3000（整场打不穿＝没有守点压力）都不成立。

#### 守点不吃己方火力（2026-11-19 修正，§4.217）

**问题**：守点是 `tier='building'`（`shellBlock:true` ⇒ 派生 `mode='solid'`）的实体掩体，**照常截停炮弹**，而掩体命中分支对任何有限 `hp` 都扣 1 点耐久。玩家守在守点旁朝敌人开火时，被守点截停的每一发都在削自己的任务目标 ⇒ 「守点被毁 = 任务失败」的把关退化成随机惩罚。

**实测**（`KIND=defend SEED=20261119`）：敌方开火分桶只有 22 发打守点，守点却掉满 60 点；把玩家火力关掉（探针 `FIRE=0`）后敌方 63 发 = 掉 60 点，账才对得上 ⇒ 差额全部来自玩家自己。

**现行口径**：

- 守点**照常挡弹**（玩家不能穿它打人）。
- 但**只有敌方火力能磨损它**：同阵营炮弹被挡下、记 0 伤害（`js/tank_fire.js` 的 `friendlyOnObjective` 分支）。
- **HE 溅射也不波及守点**（`js/tank_cover.js` 的 `splashCoversAt` 跳过 `guardTarget`）——破障不该顺带削任务目标。
- 豁免只认运行期打的 `guardTarget` 标记，**不带该标记的普通掩体（含同 tier 的 `intact`）行为逐字节不变**。

回归断言在 `scripts/test-fire.js` §4.217（7 条）：己方打不掉 / 敌方打得掉 / 非 `guardTarget` 同 tier 掩体仍被己方磨损（反证）/ 溅射不波及 / 普通掩体照常吃溅射（反证）。

### 类型身份在生成后被改写时怎么办

`applyRunKinds` 会在 `makeNode` **之后**改 kind（突破置中段、非战斗节点替换、占比回退）。因此几何不能只在生成期建一次：

- `applyNodeKindGeometry(node, kind)` 摘旧结构（按 `guardRing`/`channelWall` 标记）→ 重建 → 把压在新结构里的敌人沿 y 推出（`pad 40`）。
- 非几何类型（shop/supply/event/exterminate）若有旧结构或 `typeObjective`，**同样摘除**并置 `null`（防止「商店里长了个要塞」）。
- 三者皆无的普通节点直接 `return null`，逐字节不动。

### 失败语义：任务失败 ≠ 玩家阵亡

- 守点被毁 ⇒ 本节点**任务失败**（用户裁定：守住这个点是 defend 的唯一实质内容，改前只是 bonus 归零、清完波仍判胜利 ⇒ 类型语义不成立）。
- 但**不是 gameover**：玩家还活着、还能打完，故走**低分结算**（`defend.failScorePct`，`[PLACEHOLDER]` 0.4，低于突破超时的 0.5——任务失败比超时更重）。
- `finishEncounter` 的 `defeat` 必须带 `failReason`（`'objective-lost'` / `'player-dead'`）：页面据此分叉——后者交给既有复活/gameover 管线，前者走低分结算。**缺这个字段就是确定性软锁**（`enc.outcome` 幂等 ⇒ 后续 0 事件 ⇒ `victory` 永不到 ⇒ `battleExitReady` 永不置位 ⇒ 玩家出不去）。

## 类型体系总纲

（2026-11-01 用户裁定：三型闭环＋1 变速器）

- **寄生波次导演**：节点任务类型**只换胜利条件、敌人编排与结算奖励，不换时长结构**——全部寄生在 `js/tank_encounter.js` 的阶段机（`telegraph→wave→breather→victory/defeat`）上，新类型 = 新 condition 函数 + 新参数组，不新开管线。
- **时长护栏**：单节点目标时长 180~300s（中位 240s，见 [遭遇节奏与时长预算](./encounter-pacing.md)）。类型是时长内部的重新分配（防御 = 波次化、占领 = 读条与反冲击交织），不是新的时长容器。
- **语义层翻转，不改地图生成器**：类型改变的是点位用途、目标实体与胜利判定，不改变 `generateNode` / `generateStrip` / 路网 v4 七拓扑的产出。详见 [地图需求与生成器能力对照](#地图需求与生成器能力对照)。
- **`node.kind` 标签 + HUD 简报**：`makeNode` 写 `node.kind`（**7 型枚举**：`exterminate` / `defend` / `capture` / `breakthrough` / `shop` / `supply` / `event`；Boss 与生存节点为 `null`），节点图 HUD 显示类型标签与一句话任务简报——玩家在选卡前对胜利条件有预期（构筑动机）。
- **反支柱衔接**：类型不得引入纯赶路 / 纯潜行 / 干等读条（「不做漂亮的 41 秒」）；占领读条与战斗交织（见下）。

## 三型闭环

每型规则四件套：胜利条件 / 敌人编排 / 结算 bonus / 复用基建与成本档。

| 类型 | 胜利条件 | 敌人编排 | 结算 bonus | 复用基建 | 成本档 |
|---|---|---|---|---|---|
| **歼灭**（正名） | 逐点消灭守军（一波 = 一个防御点，E2 已落地），清完出口点亮 | 现行 `standardWaves` 原型循环派生 | 现行 `scoreNode`（无伤 / 速通 / 据点存活） | 现行全管线（零改动） | 零 |
| **防御** | 守点目标存活至波清（固定 3~4 波反冲击） | 敌人 2~4 向环带来袭（`ringSectorsBase/Max`）+ 末波总攻 | 守点目标存活 +20% 级 bonus；目标被毁 bonus 归零（非失败） | 反冲击前锋 + telegraph + 环带多向 + deployables + 可破坏建筑 | 低 |
| **占领** | 2~3 个点逐个读满（区域成员关系，读条与移动不冲突） | 读条 50% 触发反冲击前锋；读条期间敌方进入即中断 | 压点速度 / 读条被打断次数 → 得分（机动与分兵奖励） | `planDefensePoints` 选址 + 反冲击前锋 + 友军三命令 | 中 |

## 突破节点

- **位置**：路线中段，作为时间节奏变速器。
- **核心规则**：限时抵达出口（`exitX`），敌人目标是**拦截**、非全灭——玩家可打可绕。
- **失败语义**：倒计时结束未达出口且玩家存活 ⇒ 按低分结算进入 settlement（不是 gameover，防挫败）。
- **结算 bonus**：提前抵达 +20% 级 bonus；被击伤沿程折算。
- **复用基建**：`exitX`/clearing 管线 + 反冲击前锋 + 公路加速（`speedBonusKmh`）。成本档：低-中。

## 防御与占领的设计要点

（2026-11-01 用户裁定：占领语义 = 车组驻留 + 友军代守）

**防御节点**（与 survival 模式的区分）：
- survival = 无限波条带守点大图；标准防御节点 = **固定 3~4 波 + 守点目标存活判定**，收进 180~300s 预算。
- **守什么**：守「刚打下的最后一个防御点」——与 P2-G 反冲击语义无缝接续（「攻下来的阵地马上要守」，一节点内完成攻→守弧线）。
- **方向反转是关键新意**：现行标准节点 100% 玩家攻敌人守；防御节点首次让 `defenseWalls` 的墙与缺口变成玩家的掩体资产。
- **失败语义**：守点目标毁 ≠ gameover（防软锁与挫败）= 存活类 bonus 归零 + 友军重创；玩家阵亡仍走 revive 管线。
- **红线**：总攻波不得突破同屏上限 `maxAlivePerWave`（现行 8）。

**占领节点**（装甲语义，禁止步兵占旗）：
- **语义**：「车组驻留 + 友军代守」——区域内存在我方单位（玩家或受 focus 的友军）**且**区域内无敌方单位时读条；读条与移动不冲突（判据是区域成员关系，不是站立不动）；读满 = 拔点。
- **一节点 2~3 个点**：复用 E1 `planDefensePoints` 选址原语，语义从「敌人守」翻转为「我方夺」，点上的工事为敌方所用、玩家逐个夺占。
- **反冲击交织**：读条到 50% 触发反冲击前锋——读条与战斗交织，杜绝「干等读条」。
- **友军代守 = P3 高光**：玩家 focus 一辆友军进点代守、自己去顶反冲击。
- **工程车两合一（可选增强）**：读条主体换成慢速无武装工程车，玩家护送并保护展开——工程车 = 视觉/叙事锚点，友军代守 = 机制层；初版可先做纯「车组驻留」减成本（新增慢速无武装工程车实体属新实体，标价中档）。

## 轻量奖励绑定

（2026-11-01 用户裁定：类型只改胜利条件 + 轻量绑定差异化结算奖励）

- **形式**：score bonus（类型专属结算加成，走 `scoreNode` 的 bonuses 通道）+ 稀有度权重（结算选卡的保底/加权按类型微调，走 `RULES.cards` 的抽取层）。
- **意图**：让构筑流派各有主场——防御 = 部署物流（炮塔/地雷/战术掩体 + APS/护盾 + 友军 focus），占领 = 指挥流（友军代守）+ 机动流，突破 = 机动/装甲流，歼灭 = 通用基准。
- **不绑定**：不做类型专属卡池整表、不做类型专属掉落表（轻量原则，防平衡面膨胀）。

## 非战斗节点：替换不追加

- 商店节点 / 补给维修点 / 事件节点（选卡即事件）**纳入节点类型体系**。
- **护栏：替换，不追加**——每 N 战斗节点后的商店/事件节点**替换掉一个歼灭节点**，防止节点链变长、局时长雪崩（节点链长度口径需同步重排）。
- 复用：商店与补给站现成（`buildRunShopInto` / `supplyStations`）；事件节点复用普通节点地图，零新地图。

## 长期扩展池

（仅候选，不承诺排期；均需在闭环验证后再评估）

| 候选 | 一句话 | 判定要点 |
|---|---|---|
| **猎杀** | 消灭指定高价值目标（TD/SPG），余部可不打 | 目标标记 UI（非地图）；成本低 |
| **敌后破坏 → 猎杀变体** | 原「潜行摧毁目标」已**砍**（与 2026-10-31「常驻巡逻不做」裁定冲突），改造为猎杀变体并入长期池 | 需 AI 感知梯度（PLAN §4.2）落地后再评估 |
| **低可见度节点** | 视野范围压缩 + 烟幕/暴露度深化 | exposure 三档的第二场戏；机制层几乎零地图需求 |
| **双线节点** | 友军守左、玩家攻右 | 吃友军 AI；指挥流高光 |
| **精英节点** | 普通地图 + 精英编成 + 稀有度权重 | 零地图成本；「构筑检验场」而非新动词 |

## 地图需求与生成器能力对照

回答「每个类型对地图的需求 vs 现有生成器能力」。现有能力池：7 模板 `generateNode`（2100×1200 有边界）、`generateStrip` 多行片（每行横向路面保证）、路网 v4 七拓扑、`planDefensePoints` 选址（生成前期、点驱动工事）、`defenseWalls` 竖墙、`building` 三阶段可破坏、公路加速、环带 2~4 向（`ringSectorsBase/Max`）。

| 类型 | 地图需求 | 现有能力覆盖 | 缺口 |
|---|---|---|---|
| **歼灭** | 有边界战场 + 逐点防线 | 全覆盖（现行节点） | 无 |
| **防御** | 守点目标（点位+工事）+ 多向接敌空间 | E1/E3 点驱动工事 + 环带 2~4 向 | 小：守点目标实体化（`building` 生命周期现成可用作目标）+ 目标 HUD 标记 |
| **占领** | 2~3 点沿推进轴 + 点间反冲击走廊 + 驻留空地 | 按推进轴选址 + `spacingScreens=0.9` 点间距 | 小：**反转生成顺序反而利好**（点位回填前是空地，正好作驻留区）；只缺「驻留判定圈」语义（新原语，非地图） |
| **突破** | 出口明确 + 走廊线性 | `exitX`/clearing + 公路加速 + 反冲击前锋 | 无 |
| **猎杀** | 高价值目标靠后可辨识 | `layerRank` 排布（TD/SPG 压后） | 小：目标标记 UI（非地图） |
| **护卫**（长期池） | 长直路径 + 慢速单位 | 部分：`generateStrip` 横向路面正好是「车队路径」，但标准节点 2100 宽不够「横穿护送」叙事 | **中-大：最吃地图**——需 strip 化或大节点；工程车实体（无武装慢速单位）是全新实体 |
| **敌后破坏** | 潜行入口 + 目标建筑 + AI 感知边界 | 部分：exposure 三档已有 | **已砍**：AI 巡逻/感知梯度未落地且「常驻巡逻明确不做」（2026-10-31 裁定⑩） |

**结论**：六类型里四个（歼灭/防御/占领/突破）现有管线覆盖 ≥80%，缺口集中在「目标语义 + HUD」而非地图几何——这正是 E 系列「语义层翻转」路线的延续。

## 程序生成的坚持理由与例外

**坚持程序生成的理由**（三条，2026-11-01 用户确认）：
1. **确定性回放**：确定性 seed 逐字节复现是存档（`runProgress` 只存重放键）、Node 测试与浏览器回放链的基石；手搓地图破坏它。
2. **回归带**：平衡面依赖「类型 × 7 模板 × 5 难度 × seed」回归带（`test-nodegen-calibration` 锚点）；手搓图每类型单独平衡。
3. **成本**：一个程序化参数组 ≈ E1 量级，但程序化给无限变化；手搓图只有固定几幅。

**解法与例外**：
- **解法**：类型永远不改地图生成器，只改语义层（点位用途、目标实体、胜利判定）——防御/占领已证明可行。
- **例外**：护卫若落地**必须走 strip 化**（标准节点内做护卫不现实）；其余类型无例外。

## MS3 验收口径

（2026-11-01 用户裁定 MS3「内容量落地与校准」后补；本页只写**判据与阈值目标**，实施步骤归 `docs/PLAN.md` 拆分条目。）

本节的判据等级约定：**目标值**（可执行/达标即验收）；**[PLACEHOLDER]**（阈值待 `measure-encounter` 实测标定，标定前不得按体感微调，同 `RULES.encounter` 三键纪律）；**回归锚**（已达标、防劣化的既有基线）。

### 时长分解目标

单节点总时长 180~300s（与 [遭遇节奏与时长预算](./encounter-pacing.md) 同源）。按 `telegraph + wave + breather` 三段分解：

| 段 | 目标 | 依据 |
|---|---|---|
| `telegraph` | 固定开销，**不因内容量变化而放大** | 现行 2.0s/波（`RULES.encounter.telegraphSeconds`）；只随波数线性累加 |
| `wave`（真交战） | **占单节点总时长 ≥ 60%** | 现状实测（2026-10-28）：真交战 20.3s/54%、喘息 11.8s/31%——真交战须补足、喘息须压缩 |
| `breather` | **占单节点总时长 ≤ 25%** | 现状 31% 超标；收缩来源 = 喘息随规模浮动的参数组（[目标参数组](./encounter-pacing.md#目标参数组)）+ MS3 内容量校准 |
| 总时长 | 180~300s | 沿用 #AB10 目标；**2026-11-02 D1 已把口径锚定为「单节点」**。历史读数互相矛盾（91s / 50.5s / 280~300s 含撞 CAP 截断样本），**D5 干净重测出数前不得作为验收依据**（见 [遭遇节奏与时长预算](./encounter-pacing.md) 的口径告警） |

**失败信号**：单节点 < 180s（内容量不足）或 > 300s 截断且真交战占比 < 60%（时长靠喘息/赶路凑数，非真决策）。

### 非战斗节点占比

「替换不追加」的可验证判据：

| 判据 | 目标 | 依据 |
|---|---|---|
| 节点链总长 | 引入非战斗节点后，**节点链总长不增**（与同 seed 纯战斗链等长） | 「替换不追加」的硬性表达；违反 = 局时长雪崩风险回归 |
| 替换节奏 | **每 4 个战斗节点替换 1 个歼灭节点**（`[PLACEHOLDER]`，建议 N=4，实测校准） | N=4 与现行 `bossInterval=3` 错位互斥（Boss 节点不替换），替换只落在非 Boss 位 |
| 占比上限 | 非战斗节点占整链 **≤ 25%** | 上限 = 1/N；保证构筑节奏不被打断 |
| Boss 节点 | **不参与替换** | Boss 节点是构筑检验场，不是可替换的歼灭节点 |

### 构筑流派主场判据

四类型主场：防御 = 部署物流流、占领 = 指挥流 + 机动流、突破 = 机动/装甲流、歼灭 = 通用基准。可测化表达（同一把打两类的对照）：

| 判据 | 目标 |
|---|---|
| 主场流得分比 | 同一 seed、同一难度下，主场流派在对应节点类型的**结算得分中位数 ≥ 通用基准流派的 1.2×**（`[PLACEHOLDER]` 待实测标定；方向 = 显著高于，阈值实测） |
| 主场流生存差 | 主场流派在对应节点类型的**首次掉血时刻 ≥ 通用基准流派的 1.5×**（`[PLACEHOLDER]`；沿用 MS1 门 ③「首次掉血 ≥2×」的同口径思维，阈值按类型实测降标） |
| 反证（防虚假主场） | 每个类型至少一条**负向断言**：某「非主场」流派在对应类型**不得**显著优于通用基准（即主场判据不是恒真） |

**测量口径**：与 `measure-encounter` 同款探针（同 seed、同难度、同构筑对照组）；测量管线与阈值标定结果归 `docs/PLAN.md` 的 MS3 拆分条目与 `docs/DEVELOPMENT.md` §4 落地结论。

### 类型标签可读性判据

`node.kind` + HUD 一句话任务简报的可验证要求：

| 判据 | 目标 |
|---|---|
| 可见时机 | 玩家在**选卡前**能看到节点类型标签与一句话任务简报（节点图 HUD，非进战斗后） |
| 简报内容 | 一句话 = 胜利条件（歼灭 = 全歼守军 / 防御 = 守点存活 N 波 / 占领 = 拔点 2~3 个 / 突破 = 限时抵达出口）；含类型专属结算提示 |
| 数值一致性 | HUD 简报里的类型标签与 `node.kind` **同源**（不得页面内再写死类型枚举） |
| 负向断言 | 至少一条：简报在非战斗节点不显示胜利条件文案（防「商店节点显示歼灭」之类的错挂） |
