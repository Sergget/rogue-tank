## 基准分辨率与适配策略

**基准 1600×900（16:9），最小支持 1280×720，不做整体等比缩放。**

三条依据：

- **平台判定**：七页均为桌面浏览器 + 键鼠（TAB/ESC/Q/E/F/1-6/Z 按住转盘），无触屏手势，`min-width:420px` 弹窗、`height:100vh` 锁死 ⇒ 桌面横屏优先。
- **HUD 实测宽度**：底部三区（240 血条 + 7 个武器按钮 + 3 技能槽 + `gap:26px`×2 + padding）约 **1000px**。1600 宽下占 62%（舒适）、1280 下 78%（偏满）、1920 下 52%（偏空）。
- **三栏页主区**：两侧栏各 320 后，1280 剩 640（画布最小可读）、1600 剩 960（舒适）。取 1600 即「主区舒适 + HUD 不拥挤」的最小可行宽度。

**为什么不做整体 `transform:scale()`**：1280 屏上 11px 会缩到 8.8px，直接跌破下一节的硬下限。

| 做法 | 采用 | 理由 |
|---|---|---|
| 整体等比缩放（Canvas Scaler 思路） | ❌ | 小屏上字号跌破可读下限 |
| 固定 px 字号 + 弹性容器 | ✅ | 字号恒定可读，宽度靠 flex/grid 分配 |
| 媒体查询断点 | ❌（当前） | 七页为单目标形态，无移动需求 |

> 注意这与 Unity/UE 的 Canvas Scaler 思路**相反**：Web DOM UI 靠**布局弹性**换空间，不靠**缩放**换空间。

## 安全区

**分两层，不合并成同一个值**——两者冲突原因不同：

| Token | 值 | 适用 | 依据 |
|---|---|---|---|
| `--safe-hud` | **12px** | 沉浸页（battle / bench / designer / 3d）贴边覆盖层 | 战场是主角，HUD 必须尽量贴边；抬到 24px 会实际遮住 12px 宽的战场边缘 |
| `--safe-page` | **24px** | 文档页（index / compare / codex）页面边距 | 侧栏是实心面板，12px 内边距会让 320px 栏内的 28px 控件贴死边框 |

异形屏兜底：`--safe-top: max(var(--safe-hud), env(safe-area-inset-top))`（当前无需求，预留）。

## 设计令牌

**基准色板 = 暖橄榄军事终端**（原 battle/bench/compare/designer 四页现役值）。废止的两套（冷蓝灰、devPanel 沙金）见 [沿革](./changelog.md#ui-色板三套并存)。

### 语义分工（不可混用）

| Token | 值 | 语义 |
|---|---|---|
| `--amber` | `#ffb454` | **主强调 / 可交互**（按钮、焦点前的强调） |
| `--green` | `#7ed957` | 正向 / 成功 / **选中态** |
| `--blue` | `#5cc8ff` | 技能 / 友方 / 侧装甲 / **键盘焦点环** |
| `--red` | `#ff5c4d` | 危险 / 敌方 / 前装甲 |
| `--purple` | `#b98aff` | 后装甲（仅 codex / designer） |

**不得**用琥珀表示「成功」，不得用绿表示「可点击」。四色各自独占一个语义位，混用会让玩家失去颜色直觉。

### 字体

| Token | 值 |
|---|---|
| `--font-ui` | `'Rajdhani','Noto Sans SC','Microsoft YaHei',sans-serif` |
| `--font-mono` | `'JetBrains Mono','Consolas',monospace` |

**CJK 回落是必须显式写的**：`Rajdhani` 不含中文字形，缺了回落就是「各机器各自走浏览器默认」，跨平台不一致。`--font-mono` 供数值、标签、键位、表格使用。

### 间距 / 圆角 / 尺寸 / 层级

| 组 | 令牌 |
|---|---|
| 间距（8px 基准） | `--sp-1` 4 / `--sp-2` 8 / `--sp-3` 12 / `--sp-4` 16 / `--sp-5` 24 / `--sp-6` 32 / `--sp-7` 48 |
| 圆角 | `--r-0` **0**（默认）/ `--r-pill` **999px**（仅状态徽标） |
| 描边 | `--bd` 1px `--line` / `--bd-strong` 1px `--amber-dim` / `--bd-accent` 1px `--amber` |
| 控件高 | `--ctl-h` 28 / `--ctl-h-sm` 24 / `--ctl-h-lg` 36；`--w-num` 72 / `--w-text` 160 |
| 进度条高 | `--bar-thin` 4 / `--bar` 10 / `--bar-lg` 12 |
| 弹窗宽 | `--dlg-sm` 360 / `--dlg-lg` 640 |
| 栅格 | `--grid-cols` 12 / `--grid-gutter` 16 / `--content-max` 1440 / `--sidebar-w` 320 |
| 层级 | `--z-hud` 10 / `--z-overlay` 20 / `--z-panel` 30 / `--z-dialog` 40 / `--z-toast` 50 / `--z-cursor` 60 |

**圆角统一为 0（「改一处 vs 改四处」原则）**：四页已是全直角硬边，构成已确立的视觉语言；`index.html` 的 10px 圆角是唯一例外。改 1 页 ≈ 改 4 页的 1/4 成本，且直角与「战术地图 / 仪表读数」气质一致。例外只有状态徽标走 pill。

**2px 边框只在两处「状态强调」**：`#quotaHud` 的左侧定位条、`.dmg-toast-line` 的警告框。其余一律 1px。

> 层级令牌是**目标值**，现役数值与之不符（如 `#skillSlotPicker` 60、`#bossBriefing` 70）。改动会实际改变叠放顺序，属 P2 且需逐项人工核对——**做不到就保留现状，不要盲改**。

## 字号阶梯

**5 档：11 / 13 / 16 / 20 / 32，级差 ≥2px，11px 是硬下限。**

| Token | 值 | 行高 | 语义 |
|---|---|---|---|
| `--fs-hero` | 32px | 1.1 | 封面主标题（仅 `index.html` h1） |
| `--fs-h1` | 20px | 1.2 | 弹窗主标题、大数值读数（速度表、波次计数） |
| `--fs-h2` | 16px | 1.3 | 面板标题、卡片标题、页头页名、警告 toast |
| `--fs-body` | 13px | 1.5 | 正文、按钮文字、列表项、表格主列、任务卡 |
| `--fs-xs` | 11px | 1.4 | 标签、角标、单位、键位提示、表格次列、元信息 |

### 为什么下限是 11px

**这不是审美判断，是本项目已有实证。** [HUD 与界面](./hud-ui.md#左下角目标卡与提示条可读性口径aa82026-10-26) 记录：用户反馈「标准模式左下角任务描述在某些 biome 看不清」，根因是 `#quotaHud` 的 10px + 暗色 + 无底衬；现行已抬到 11px 并加底衬，`scripts/test-hud-readability.js` 因此把 11px 锁成断言。

⇒ 10px 及以下在本项目**已被用户判定为不可读**。

### 为什么正文是 13px

- 与下限 11px 必须形成 **≥2px 级差**才有层级感；12px 只差 1px，会重演「9 vs 10 分不清」的老问题。
- 14px 会使 `#bottomHud` 三区总宽再涨 8%，1280 下溢出风险显著上升。

### 为什么定「级差 ≥2px」

原实现有 8 档挤在 15px 以内，`9px` 与 `10px` 只差 1px，语义上无法区分、只能靠记忆，最终导致同一语义的元素在不同页取了不同值（`#homeSlotList .slot-meta` 9px vs `#shopUpgradeList .sdesc` 10px，两者都是「卡片次要说明」）。**级差 ≥2px 是防止这类漂移复发的结构性约束。**

### 豁免区

`#devPanel` / `#logPanel` / `#fpsReadout` / `#testDebugHud` 保持原字号——它们是**开发者诊断工具**，非玩家 UI，密度优先。

## 栅格与页面骨架

### 页面分两类

| 类 | 页面 | 根样式 | 安全区 | 滚动 |
|---|---|---|---|---|
| **A 沉浸页** | battle / bench / designer / 3d | `height:100vh; overflow:hidden` | `--safe-hud` | 页面不滚；内部面板各自 `overflow-y:auto` |
| **B 文档页** | index / compare / codex | `min-height:100vh` | `--safe-page` | 页面可滚；顶栏 `position:sticky; top:0` |

### A 类用绝对贴边，不用列栅格

战斗 HUD 是**仪表贴边**，不是排版：四角锚定 `left/right/top/bottom: var(--safe-hud)`；中央元素 `left:50%; transform:translateX(-50%)`；同角多元素一律**纵向 flex 栈容器**统一管间距（`#topCenterHud` 是正确范例）。

垂直预算（720 高最小屏）：顶部 ≤ 42px、底部 ≤ 78px、**中央战场 ≥ 600px 且不被遮挡**。

### B 类用 12 列栅格

列数 12 / 边距 `--safe-page` / 栏间距 `--grid-gutter` / 内容最大宽 `--content-max`（1440，超出居中）/ 尺寸对齐 4px 倍数。

### 三栏工具页侧栏固定 320px（P2 未落地）

现役 `bench` = `300px 1fr 340px`、`designer` = `20vw 1fr 380px`、`codex` = `300px 1fr`，目标统一 `320px 1fr 320px`。

- **下限**：`bench` 左栏 `bar-row` 需 `label 64 + gap + track + val 44` ≈ 220 内容宽，加 padding 24 + 边框 2 ≈ 246px；`designer` 右栏 `armor-row`（swatch 10 + 输入 64 + label）需 ≥300px。
- **上限**：1280 下两侧栏各 320 后主区剩 **640px**；取 360 则只剩 560。
- **`20vw` 必须改掉**：它在 1280 下变 256（不够 `armor-row`）、1920 下变 384（`edge-list` 过宽），是典型的随分辨率漂移写法。

### 弹窗两档：360 / 640

| Token | 用途 | 现役 |
|---|---|---|
| `--dlg-sm` 360px | 轻确认（技能槽指派） | `#skillSlotPicker` `min-width:280` |
| `--dlg-lg` 640px | 主流程（地图/结算/卡牌/Boss 简报） | `#flowOverlay` 420~640、`#bossBriefing` 560 |

**640 是算出来的，不是凑的**：卡牌三选一 `3 × 180 + 2 × gap 16 = 572`，加弹窗 `padding 2×24 + 边框 2 = 622` ≤ 640 ✓。再小一档就装不下三张卡——这正是现役 420~640 浮动、卡片靠 `flex-wrap` 换行的根因。

所有弹窗补统一约束：`max-width:92vw; max-height:84vh; overflow-y:auto`。

## 迁移状态与验收

三期路线，P0 已落地：

| 期 | 内容 | 状态 |
|---|---|---|
| **P0** | 抽 `js/tank_ui.js`、七页接线、删 6 处重复 `:root`、冷调/沙金并入暖橄榄、圆角归零、首页改版 | **已落地（2026-10-27）** |
| **P1** | 字号 5 档收敛、间距归并 8 栅格、控件高 28px | 未落地 |
| **P2** | 侧栏 320、弹窗 360/640、卡片 180、进度条三档、按钮五态、z-index 六层 | 未落地 |

**P1 的风险与复核点**：11→13 会让文本宽约 18%，`#bottomHud` 三区在 1280 下可能压到战场。逐页单独提交，每页复核：HUD 按钮（30px 高）内是否溢出、`#abilityQuota` 是否折行、`#flowOverlay .screen` 是否撑破、三栏页侧栏高度是否溢出。

### 验收命令

```bash
node scripts/test-ui-tokens.js        # 令牌契约（七页接线/无重复/无废止色/字号棘轮/圆角）
node scripts/test-hud-readability.js  # 字号下限与底衬（#AA8 契约）
node scripts/check-html.js            # 结构 + 测试链登记一致
node scripts/wiki-check.js            # 改过 docs 后必跑
```

**字号棘轮机制**：`test-ui-tokens.js` 的 `FONT_BASELINE` 记录每页每个字号的出现次数上限，断言**只减不增**。P1 每收敛一处，把对应数字调小；回潮即失败。这样「字号阶梯」不靠自觉，靠数字逐步逼近 5 档。
