> **摘要**：以可玩真 3D 切片验证品质，保留二维模拟，量产前设技术与美术验收门。

## 1. 目标拆解与技术裁定

《变节行动》式品质不是「Canvas 换成 WebGL」一个动作。目标拆为五个可验收维度：

1. **空间与资产**：真实体积、统一光照/材质、精细载具与主题场景；
2. **载具重量感**：加速/制动、抓地/侧滑、俯仰/侧倾、悬挂、落地和碰撞反馈；
3. **破坏与互动**：建筑/围墙/爆炸物的状态变化、残骸、地表和烟幕/火焰联动；
4. **战斗演出**：后坐、弹着材质、烟尘/火花/焦痕、声音与镜头反馈统一分级；
5. **可读性与节奏**：敌我/射界/距离清晰，镜头服务驾驶和指挥，内容有张弛。

据此：

- **不全量换引擎重写**：现有 `resolveHit`、几何、AI、卡牌、经济与节点流程是可保留资产，迁移它们不是画质升级的必要成本。
- **不继续以路线 A 为最终方案**：Canvas 侧壁/y-sort 能提升体积感，但无法满足精细真 3D 场景、材质、动态破坏与资产量产需求。
- **首选渐进渲染替换**：Three.js/WebGL 先接同一场景的只读模拟快照；现有 Canvas 作为迁移期对照/回退，不一次删除。
- **备选引擎需要证据**：只有切片证明 JS 集成/性能/资产工具链存在结构性阻碍时，才重评 Godot 等方案；重评须列出重写范围、时间、测试与存档迁移，不以「商业游戏都用某引擎」论证。

### 1.1 模拟与视觉的权威边界

| 层 | 权威内容 | 约束 |
|---|---|---|
| 二维模拟 | 世界 XY、坦克/掩体碰撞、射线命中、装甲/模块伤害、AI、命令、卡牌与经济 | 保持确定性；视觉对象不得直接写命中/伤害 |
| 场景表现 | mesh、材质、光照、阴影、相机、粒子、悬挂/碎片、声音 | 从模拟快照派生；插值不改逻辑位置 |
| 交互适配 | `screenToWorld` / 射线与地面平面求交、世界/屏幕标记 | 唯一坐标入口；输入最终仍落到二维世界 |
| 美术破坏 | 碎片、裂纹、焦痕、倒塌动画 | 玩法通路/命中变化必须由模拟层显式状态决定，不能由动画碰撞偶然决定 |

**不默认引入 3D 刚体作为权威物理**。若未来需要可驾驶垂直地形、桥梁上下层、越肩射击或高度命中，必须另开玩法设计与回归批次，不能随渲染迁移偷渡。

## 2. 从灰盒到量产的阶段

| 阶段 | 交付 | 允许进入下一阶段的证据 |
|---|---|---|
| **R0 地基** | I3 浏览器截图基线、I4 拾取唯一入口、固定 seed/视口/相机场景、Canvas 对照、帧时间/内存计数 | 输入/坐标/截图可复现；记录性能基线；不改正式战斗表现 |
| **R1 技术切片** | 一张小战场，1 辆玩家车 + 2～4 辆友军，道路/建筑/树石，轻倾斜相机，主炮、烟尘与基础破坏 | 可驾驶/命中/指挥；二维结果一致；1080p 目标机实测；失败能定位渲染或逻辑 |
| **G1 品质切片** | 精修单车与单主题场景、载具重量感、分级破坏、炮火/音效/震屏、3～5 分钟完整遭遇 | 实机尺度评审达到内部目标；敌我/射界/命令清楚；性能与可读性在峰值效果下仍合格 |
| **技术定型** | 渲染方案、资产规格、迁移顺序、性能预算、测试/存档兼容与成本估算 | 明确保留 JS + Three.js 或备选引擎的可执行迁移书；未过门不量产 |
| **M1～M3 量产** | 核心系统、主题内容、发行完整度 | 每批先过玩法与 1× 实机验收，再扩内容数量 |

R1 与 A0 友军指挥原型共用场景和命令回放脚本。**只交付旋转相机、高模或粒子演示不算 R1。**

### 2.1 R0 地基落地状态（2026-10-27）

| 子项 | 状态 | 落点 |
|---|---|---|
| **I3 截图基线** | ✅ 已落地 | `scripts/browser-baseline.cjs`：三个固定场景（standard / boss / survival），1280×720、seed `20261027`、`Math.random` 固定序列（开战前重置）、**进入战斗前冻结模拟**、绘制时钟锚定 `battleStartMs + 500`。判定用 32×18 网格（容差 mean≤2 / max≤16；实测连跑三次 mean ≤0.011 / max ≤5），每场景另存 PNG 作为 Canvas 对照图 |
| **I4 拾取统一入口** | ✅ 已落地 | `js/tank_camera.js` 的 `pointerToWorld(cam, rect, clientX, clientY)`；battle 的鼠标/滚轮与 bench 的鼠标全部改走它。真 3D 时只需把这一处换成「屏幕射线 × 地面平面求交」，`mouseWorld` 契约不变 |
| **性能计数** | ✅ 已落地 | `js/tank_perf.js` 环形缓冲（240 帧）+ battle 主循环逐帧记录 update/draw；`__TEST__.perf()` / `__TEST__.mem()` 读取 |
| **固定 seed / 相机** | ✅ 已落地 | `__TEST__.setSeed` + `__TEST__.battleStartMs`；相机在 `enterBattle` 瞬间对齐出生点，冻结后不再漂移 |

**边界**：R0 不改正式战斗表现；截图取的是「进入战斗后第一帧」的冻结快照（不含 AI 推进后的画面）。基线是本地产物，跨机器不可移植（见 `editor/browser-tests.md`）。

## 3. Go / No-Go 门槛

### 3.1 操控、判定与可读性

- 同一输入/seed 下命中、伤害、AI、命令与资源结果与二维基线一致；渲染帧率不改变模拟结果。
- 鼠标地面求交与现有 `screenToWorld` 基线一致；HUD、威胁方向、友军命令标记经同一坐标适配。
- 1080p 实机尺度下能识别玩家/友军/敌军、炮口方向、建筑高度、掩体边界与致命区域。
- 轻倾斜视角验证距离与射界判读；遮挡淡化/屋顶隐藏只改可见性，不改真实命中。
- 震屏、闪光、烟尘与动态阴影均有强度/降级设置；不能用关闭关键信息换画质。

### 3.2 手感与演出

- 加速、制动、侧滑、碰撞与落地在视觉/声音上有重量，输入响应不被动画锁死。
- 不同口径的后坐、炮口、弹着、低腔与余韵形成一致强度等级；命中和未击穿可听/可见地区分。
- 建筑与场景破坏至少验证「完整 → 受损 → 毁伤/残骸」状态，通路变化与模拟一致。
- G1 以**实机驾驶与战斗录屏**评审，不只看静态截图；内部须先保存参考目标与逐项差距，避免「接近」变成不可验收形容词。

### 3.3 性能与工程

实施前把目标机、分辨率和帧时间写入测试记录；下列为预算维度，不是未实测的验收数值：

| 预算 | 必测内容 |
|---|---|
| CPU/模拟 | 同屏单位、友军命令/导航、破坏状态、粒子逻辑；不得为救帧降低权威模拟频率 |
| GPU/场景 | draw call、三角形、阴影、透明粒子、过绘、材质切换；实例化与 LOD 前后对照 |
| 内存/加载 | 模型/纹理/音频、地图切换峰值、缓存上限、资产压缩与首次加载 |
| 回归 | 固定场景截图、确定性回放、现有 Node/浏览器链、存档迁移与崩溃诊断 |
| 降级 | 阴影/碎片/粒子/分辨率档位只降表现，保留敌我、命中与命令信息 |

No-Go 时先修投影、资产/性能或表现，不进入地图和车型量产；若同一结构性阻碍在修整后仍无法过门，才启动备选引擎评审。

## 4. 资产生产与「无建模基础」的适用边界

2026-10-24 的就绪度研究只证明了**原型几何可由现有 JSON 参数化生成**，并未证明商业品质不需要美术。2026-10-26 起统一按两级资产管理：

| 级别 | 来源与用途 | 验收 |
|---|---|---|
| **灰盒/原型** | `hull/turret.verts` 挤出、炮管参数圆柱、cover OBB、树木 blob、现有程序纹理 | 比例/锚点/法线/拾取正确；只用于 R0/R1，不作为 G1 精修完成依据 |
| **精修/量产** | 硬表面模型、低模/LOD、UV/PBR、地表、损坏状态、VFX、音频；可外制或由工具辅助生成 | 1× 实机尺度、材质/光照统一、剪影与部件可读、损坏/锚点/性能/授权全部验收 |

- 现行「本仓库不出图、程序化烘焙 + 后期 PNG 接线」仍是 Canvas 实机规则；R1 新增 3D 资产管线时另建目录与验收，不把 PNG 冒充 3D 模型。
- glTF 为候选交换格式，具体 DCC/导出工具、纹理规格、单位和坐标系在 R0/R1 固定；不在未验证前大量转换资产。
- 需要模型/材质/场景/特效能力，但不等于必须学习角色或有机建模；硬表面与场景精修是不可省略的工作包。
- 素材许可、字体、音频与参考资产用途从入库时登记，商业合规不拖到发行前补票。

## 5. 远期工作包与顺序

| 顺序 | 工作包 | 依赖/边界 |
|---|---|---|
| 1 | 渲染与资产管线、相机/拾取、性能与截图回归 | R0 先行；所有后续工作的共同地基 |
| 2 | 友军指挥、载具手感、战斗可读性 | 与 R1 同场验证；是游戏身份，不是画面附属 |
| 3 | 破坏、战斗演出、地表互动与声音 | 明确玩法/视觉状态边界，逐主题接入 |
| 4 | 遭遇导演、主题地图、任务变体、Boss 演出 | G1 后；避免纯血量/数量扩难度 |
| 5 | Run 节奏、车库、卡牌/友军协同与重玩性 | 内容组合验证后扩量，不孤立堆卡 |
| 6 | 手柄、I18n、Deck、设置/可访问性、回放/存档/诊断 | 输入/词条/版本/性能地基提前，完整打磨在量产期 |
| 7 | Steam 成就/云存档/封装/商店与可选 Workshop/排行榜 | 发行候选期；排行榜可单机异步，不引申实时多人 |

**优先级**：手感与可读性 > 友军命令可靠性 > 破坏与演出 > 内容数量 > 平台扩展。多人合作不是后续默认项。
